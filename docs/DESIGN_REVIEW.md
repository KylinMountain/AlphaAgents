# AlphaAgents 设计评审材料

> 写给外部评审者。文档日期 **2026-09-11**。所有数字来自当天的真实数据库查询，
> 不是设计意图，也不是估算。有多少写多少，包括难看的部分。

---

## 0. 我们想要评审什么

这个系统**不是**一个选股模型，也不是一个信号回测框架。那条路线在隔壁项目
（`alphaquant`，LightGBM 监督学习）并行跑着。

这个项目要做的是另一件事：

> **养一个会交易、会复盘、会因为亏钱而改变行为的交易员。**

所以我们想被评审的不是「胜率能不能更高」，而是：

1. **抽象对不对** —— 用「可证伪的论点（Thesis）」承载一个仓位，是不是
   把交易变成可学习问题的正确切法？
2. **闭环成不成立** —— 从决策到结果到修正，这条链上有没有断掉的环，
   有没有在给错误的东西打分？
3. **代码与 agent 的边界划在哪里** —— 见第 4 节，这是我们最近争论最激烈的地方。
4. **样本效率** —— A 股短线，一天 1-2 笔，一年 250 个交易日。在这个样本量下
   「学习」到底可不可能？如果不可能，那什么是可能的？

**请优先挑毛病。**附和对我们没有价值。

## 1. 北极星

**Trade · Learn · Evolve** —— 三个词都要是字面意思：

- **Trade**：它要真的做出决定（买不买、买在哪、多大仓位、什么时候走），
  而不是产出一份「建议关注」的报告。
- **Learn**：每个决定都要留下**可以被后来的事实判对错的痕迹**。一个无法被
  证伪的判断不算判断。
- **Evolve**：判断的质量要能改变后续的行为。**不是**靠人去改 prompt，
  而是系统自己把「反复答对的判断」沉淀下来、把「反复答错的」淘汰掉。

一个反面参照，也是我们最想避免的形态：
**一个更聪明的推荐器**——每天给出更好的名单，但一年后和第一天一样，
没有任何东西因为它亏过钱而不同。

### 2.2 一天的时间表

调度器按交易日感知运行（`main.py` 注册，`pipeline/scheduler.py` 执行）：

| 时间 | 任务 | 用 LLM | 说明 |
|---|---|---|---|
| 全天每 5 分钟 | `news_ingest` | 仅 embedding | 13 源摄取 + 向量索引。**不做判断** |
| 09:00 | `morning_scan` | ✅ 每个交易员一次 | 选股 + 建论点 |
| 09:25 | `opening_reminder` | ❌ | 集合竞价末端播报 |
| 09:30–15:00 每 5 分钟 | `intraday_monitor` | ✅ 条件触发 | 异动归因 + 定价 + 持仓管理 |
| 15:30 | `review` | ✅ | 复盘、结算、喂学习系统 |
| 20:00 | `night_scan` | ✅ | 外盘 |
| 周六 10:00 | `weekly_report` | ✅ | 周报 |

盘中监控**不是每轮都调模型**。只有异动扫描判定「今天有新东西」时才往下走，
且有 40 分钟的新颖性去重（`_is_novel`），否则同一个信号会每 5 分钟重放一次。

### 2.3 多交易员

每个交易员是一个 YAML 文件（`traders/*.yaml`），**加一个策略不需要改代码**：

```yaml
id: pullback
name: 回调派
capital: 1000000
prompt_file: morning_scan.md
default_size_pct: 0.05
max_position_pct: 0.10
extra_prompt: |
  你偏好回调买入…
```

按 `trader_id` 隔离的：资金、持仓、论点、预测、校准曲线、盲点率、一致性、
过程质量、净值曲线、回撤、行业集中度。
**共享**的：行情、主线、新闻、工具。

设计上刻意**没有** `entry_style` 这类字段——曾经有过，被删掉了。理由见第 4 节。

### 3.1 论点（Thesis）——这是核心抽象

一个仓位不是「买了某只票」，而是**「为了一个可证伪的主张而持有」**。

```
claim:      "光迅科技 跟随央企国企改革主线，高beta+流动性好"
horizon:    5 天
prob:       0.58          ← 它自己给的概率，进校准曲线
conviction: 0.16          ← 信念强度，和仓位大小分开记
conditions: [
  {kind: "theme_daily_score_below", value: 0},
  {kind: "price_below",             value: 17.4},
  {kind: "drawdown_from_peak",      value: 8},
]
```

**11 种条件是一个封闭词表**，prompt 里的词表由代码从同一张表渲染
（`prompt_vocabulary()`），所以 agent 不可能提出一个校验器读不懂的条件：

| kind | 含义 |
|---|---|
| `price_below` / `price_above` | 股价跌破/升破 X 元 |
| `drawdown_from_peak` | 从峰值回撤超过 X% |
| `loss_exceeds` | 浮亏超过 X% |
| `theme_strength_below` | 主线累计强度跌到 X 以下 |
| `theme_daily_score_below` | 主线**今日分**低于 X（当天转弱，比累计更早） |
| `theme_flow_negative` | 主线资金净流出超过 X 亿 |
| `theme_rank_worse_than` | 主线掉出板块排名前 X |
| `breadth_below` | 市场涨跌比跌破 X |
| `no_progress_by_day` | 持仓 X 天仍未走出方向（±1% 内算没走出） |
| `narrative` | 无法机械判定，写在 note 里，收盘前安排一次模型复核 |

四种结局：`invalidated`（条件被触发）/ `validated`（主张兑现）/
`expired`（到期未证伪也未兑现）/ `blind_spot`（**亏钱了但没有任何一个条件触发**
——这是最有价值的一类，说明当初根本没想到这个风险）。

**为什么这样切**：它让「学习」有了明确对象。不是学「这只票会不会涨」，
是学「**我说出口的那个失效条件，是不是真的是失效条件**」。

## 4. 代码与 agent 的边界（最近改过，想重点听意见）

这条原则我们反复推翻过两次，目前的版本是：

> **代码承担已经被验证过的判断，和不可逆的风险边界。**
> **agent 承担还没有答案的判断。**
> **一个判断从 agent 手里移交给代码，必须是它反复答对之后的结果——那个移交过程本身就是 Evolve。**

三个真实案例：

### 案例 A：删掉 `entry_style`（代码 → agent）

曾经的设计：交易员配置里写死 `entry_style: pullback_3pct`，代码算
`price * 0.97` 当买入价。**113 笔订单里有 109 笔是这个常数定的价。**

问题不是保守，是任意：中钨高新日均波动 5.6%，通源石油 6.1%，给它们 3% 的
区间比一个平常的交易日还窄，全部以「价格已涨走」取消。

现在：给 agent 一个 `get_price_levels(code)` 工具（返回 ma5/10/20/60、
vwap、20/60 日区间位置、`atr_pct`、上下最近支撑阻力、缺口），
**只给事实，不给建议**，让它自己定区间、止损、仓位。

刻意保留的硬约束：解析器**绝不回退到常数**。缺止损、区间倒挂、止损落在
区间内、没写理由——全部丢弃，本轮不下单。宁可不交易，也不让常数从错误
路径溜回来。

### 案例 B：主线过滤（保留在代码里）

`_worth_asking()` 只剩两条过滤：主线不在跟踪列表、主线强度 < 4。
理由不是「这样胜率高」，而是**这两种情况下订单在创建时就会被拒**——
为它定价不是剥夺判断权，是做一件不可能有结果的工作。

（博敏电子那天被定价两次，分别挂在「存储芯片」和「先进封装」上，
两个订单都死在创建环节，思考的 token 全部白付。）

### 案例 C：把「否过」从墙改成记忆（今天刚改）

2026-09-10，301511 在一个上午被定价 **19 次，被否 19 次**，理由几乎是同一句话。

第一版修法是设墙：否过就 40 分钟内不再问。token 省下来了，
**省掉的恰恰是省 token 的目的**——它再也不会发现那只 12.40 嫌贵的票现在 13.60 了。

关键认识：**它从来不缺决定权，它缺的是记忆。一个没有记忆的 agent 不叫
「自己决定」，叫「重复初遇」。**

现在候选带着它自己说过的话回去：

```
● 600835 东方明珠 现价 19.80 今日 +6.20%
  主线: AI应用
  ⟲ 35 分钟前你看过这只票并决定不买，当时 18.10，
    理由：position_pct=92，距20日线还有4.1%，不追。
    现在 19.80（+9.4%）。变了吗？
```

实测验证（真实模型调用）：它的回答里写了
**「position_pct 从 92 降至 35.6」**——读了记录的理由，去核对那个数字还成不成立，
然后改了主意并说明改的是哪一个数。这是想要的行为。

**想听评审意见的点**：这条原则是不是在给「什么都交给 agent」找借口？
反过来，把已验证的判断固化进代码，会不会在系统真正学会之前就把路堵死了？

## 5. 学习闭环

```
平仓 / 论点结束
      │
      ├─> predictions 表：prob → brier / log_score / excess_return / residual_alpha
      │   （校准曲线：它说 70% 的时候，实际兑现多少）
      │
      ├─> consistency：它说的和它做的一致吗
      ├─> process_quality：理由的信息量（"技术面支撑"这种等于没写）
      ├─> blind_spot 率：亏了但没有一个条件触发的比例
      │
      ├─> daily_lessons（复盘课）→ trading_principles（原则）
      │
      └─> holdout_gate：一条原则要进生产，必须在留出样本上验证
          MIN_VALIDATION_SAMPLES = 20
```

**这里有一个我们自己发现的严重问题**（已修但值得评审看）：
Brier 校准机制一度在给**交叉验证器**打分，而不是给做决定的 agent 打分——
即在评价一个不做决定的角色。

## 6. 实测基线：诚实的负面结果

用 7.7M 行日线跑的，样本期 2026-03 到 2026-09（**只有 6 个月，单一下跌市**，
这是已知的样本缺陷）：

| 检验的假设 | 样本 | 结果 |
|---|---|---|
| 放量（成交量 z>2）后买入 | 45,866 | 后 5 日超额 **−0.21%**，胜率 43.1% |
| 巨量（z>4） | 14,165 | **−0.50%**，胜率 41.0% |
| 收盘位置区分「承接 / 派发」 | 45,866 | 三档无差别，方向还相反 |
| 板块热度日间持续性 | 3 天快照 | 资金前 10 **日间只重合 1/10** |
| 大涨股能否被新闻解释 | 25 只涨停 | 语义检索命中 92%，真·前瞻催化剂 **< 20%** |
| 涨停后动量 | 13,953 | **+0.98%/1日，+1.34%/3日**，第 5 日衰减 |
| 市场基线胜率 | — | 45% |

**我们对这张表的解读，也想被评审。**

我们一度据此得出「新闻驱动不成立、异动驱动不成立、主线驱动也不成立」，
后来判定这个推理是错的：「放量后 5 日超额 −0.21%」的真实含义是
**「无脑买入所有放量股、闭眼持有 5 天」的平均值**——没有交易员会这样做。
一条机械规则的负期望，恰恰是需要判断力的理由。

所以这张表现在的定位是**靶子**：agent 的判断如果打不赢这些数字，
它就没有在真的判断。

另外两条明确的「不要重走」：

- **不要**把威科夫的「建仓/承接/派发」搬到 1-3 天的题材行情上。那个框架预设
  主力用几周吸筹，而这里的「主力」是 9:31 买入、14:00 卖出的游资。
  **没有建仓阶段可以检测。**
- **不要**相信语义检索的高命中率。25 只涨停「命中」92%，实际八成是
  事后行情描述、交易所问询回复（有 4 只是「未发生重大变化」——
  **连公司自己都说没原因**）、或者完全误匹配。

最后这条引出一个设计风险：我们要求 agent 每个决策必须写理由。
**如果它被迫为每次上涨编一个原因，它会学会编。**
所以「不知道为什么，所以不做」需要是一等公民的答案，而且要统计
它说不知道的比例——一个从不说不知道的交易员，不是自信，是没在思考。

## 8. 已知缺陷与未验证的假设

**按我们自己判断的严重程度排序。**

### 8.1 漏斗几乎全部死在同一个常数上

`MIN_THEME_STRENGTH = 4` 杀掉了约 90% 的订单，**而这个阈值从未被验证过**。
它是拍脑袋定的。主线强度是一个 0-10 的累计分，每天按信号加减，
`>=4` 才允许下单、跌破 4 转 `declining`。

没有任何证据表明 4 比 3 或 5 更好，也没有证据表明「主线强度」这个
合成指标本身有预测力。

### 8.2 11 种失效条件里，实际只有 1 种开过火

39 个论点，4 个结束，**4 个都是 `theme_daily_score_below`**。
另外 10 种条件在真实运行中一次都没触发过。

之前已经查出 3 种条件是**结构性不可能触发**的（判定逻辑读不到需要的字段）。
剩下的是样本太少还是还有更多死条件，不知道。

### 8.3 反复出现的同一个 bug 形态

> **在一个被截断的市场视图里查找持仓——而一个持仓恰恰在它开始要紧的时候
> 掉出那个视图。**

已在 4 处发现并修复。最典型的一处：`_refresh_theme_strengths` 只取涨幅榜
前 20，跟踪的主线不在榜上就整个跳过——结果「小金属概念」的评分冻结在
昨天的值，而当天这个板块跌了 1.22%、净流出 45.8 亿。

**这是一类而不是一个 bug**，评审时值得专门找这个形态。

### 8.4 最高价值的两个产出正在丢失（今天刚发现）

2026-09-10：
- `morning_scan` 有 `last_run=09:27:44`，**但 reports 表里没有当天的晨报**
- `review` 有 `last_run=15:50:26`，token 计量显示它跑了 4 次调用、
  产出 4,661 output tokens，**但 reports 表里没有当天的复盘**

09-09 两者都正常入库（晨报 6 篇、复盘 1 篇）。中间发生了什么还没查。
复盘是整个学习闭环的入口，它的产出丢失等于当天没有学习。

### 8.5 校准曲线还是空的

170 条预测，`brier` 全为 NULL。校准需要真实平仓结果，而 3 个交易日只产生了
4 个已结论点。按每天 1-2 笔成交、持仓 3-10 天估算，
`holdout_gate` 的 20 个验证样本**大约需要两周**才够。

**卡点不是代码，是样本量。**

### 8.6 55 万条分时快照，一次都没用于日内决策

系统对一天里的所有时刻一视同仁。没有「开盘半小时不动手」，没有「尾盘看承接」，
没有做 T，agent 甚至**不知道现在几点、离收盘还有多久**。

### 8.7 定价质量：prompt 讲了但没管住

今天的实测里，模型在被明确告知「atr_pct=3.17%，区间比它窄基本不会成交」
之后，仍然给出了 **1.1% 宽**的介入区间。窄带告警响了，但那只是日志。

这暴露一个更一般的问题：**我们有大量「写在 prompt 里的规矩」，
没有任何机制知道它遵守了多少。**

### 8.8 样本期缺陷

第 6 节所有实测都是 6 个月、单一下跌市。在牛市或震荡市里这些结论可能全部翻转。

### 8.9 「主线」这个概念本身

主线强度混合了新闻命名、板块涨幅、资金流三种异质信号，用一个加减法累计成
0-10 的分。实测显示**板块资金前 10 的日间重合度只有 1/10**——
如果热度本身不持续，那么一个累计型的强度分在度量什么？

## 9. 请重点评审的问题

按我们认为的重要性排序。**希望看到反对意见，不是确认。**

1. **抽象层面：Thesis 是不是正确的切法？**
   把仓位定义成「为一个可证伪主张而持有」，用封闭词表的失效条件来判定结束——
   这是不是把一个连续的、模糊的交易决策过度离散化了？真实交易员的退出
   往往说不出是哪条具体条件触发的。`blind_spot` 这一类能兜住这个问题吗？

2. **闭环层面：我们在给正确的东西打分吗？**
   现在打分的对象是「它给的概率准不准（Brier）」+「理由的信息量」+
   「说的和做的一致吗」+「盲点率」。**有没有漏掉更重要的维度？**
   尤其：**94 笔订单死于「主线走弱」，这些从未成交的决定该不该进校准？**
   我们目前完全不给它们打分——一个从没成交的判断，到底是判断错了，
   还是定价错了，还是根本不该被算作一次判断？

3. **样本效率：在这个数据量下，「学习」可能吗？**
   一天 1-2 笔，一年 250 个交易日。要在多少个已结论点之后，
   校准曲线才算有信息？如果答案是「几百笔」，那这个项目的时间尺度是几年。
   **有没有办法把学习信号的密度提上去，而不失真？**
   （我们想过的一个方向：对那 94 笔被取消的订单做反事实重放——
   如果当时成交了会怎样。日线数据足够，但这是在用一个未发生的世界训练。）

4. **边界层面：第 4 节那条原则站得住吗？**
   「代码承担已验证的判断 + 不可逆风险边界，agent 承担还没答案的判断，
   移交过程就是 Evolve」——
   这是一条真原则，还是一句听起来对的话？怎么判断一个判断「已经被验证」？
   我们目前没有任何自动化的移交机制，全靠人看着办。

5. **成本层面：单日 425 万 token 换 0 笔成交，合理吗？**
   输入输出比 20:1。这是「思考很贵」的正常代价，还是架构在反复递送
   它本该记住的东西？

6. **最根本的：这条路本身。**
   如果你认为「用 LLM 养一个会进化的短线交易员」在 A 股短线这个
   信噪比下根本不成立，请直说，并说明在什么条件下它会成立。
   我们更怕的是花两年做一个永远学不会的东西，而不是被否掉。
