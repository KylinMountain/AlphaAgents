## 1. 这个项目是什么

> **养一个会交易、会复盘、会因为亏钱而改变行为的模拟交易员。**
> （This is an A-share paper trader that turns every trade into evidence for its next decision.）

三个词定义它（设计文档 §2 的定义，不是我概括的）：

| 词 | 含义 |
|---|---|
| **Trade** | 在信息、现金、持仓、风险约束下决定**入场 · 加仓 · 持有 · 减仓 · 退出 · 放弃** |
| **Learn** | 把观察到的**结果**与**解释**分开，提出**可证伪**的改进，带**支持与反对**两边的证据 |
| **Evolve** | 只在**独立前向评估 + 授权**之后替换一个**冻结**策略；证据不足就**保留在位者** |

**交付顺序不可颠倒**，设计文档原话是 *"more reports or agents cannot substitute for that
order"*：可信的交易事实 → 可归属的学习 → 可验证的进化。

## 2. 它**不是**什么（先说清，省得评错方向）

- **不是选股模型，不是信号回测框架。** 那条路线在隔壁项目（`alphaquant`，LightGBM 监督学习）并行跑着。
- 所以我们想被评的**不是「胜率能不能更高」**，而是：这个抽象对不对、闭环在给正确的东西打分吗、
  在这个数据量下「学习」到底可能吗。
- **也不是一个「agent 自由发挥」的系统。** 一条明确的原则贯穿其中：**代码承担已经验证过的判断
  与不可逆的风险边界，agent 承担还没有答案的判断，而移交的过程就是 Evolve。**

## 4. 现在走到哪了（全部为 2026-09-16 实测）

| | 状态 |

| 为什么没晋升 | 门槛要 **20 个配对样本**，影子实验进度 **0/20**；而且账本选择还没定 |

| 测试 | **2025 passed / 18 skipped**（18 个显式标注「需要真实市场语料」） |
| 价格历史 | `daily_kline` **775 万行**，2020-01-02 → 2026-09-15 |
| 新闻历史 | 本地归档 **982,533 条**；其中财联社**历史回填 935,850 条**，覆盖 2020-01-01 → 2026-09-15 |

**这一周内新发生的三件事，评审时应当知道：**

1. **新闻历史现在有了**（上面那 935,850 条），且与价格窗口精确重合 → **入口侧第一次可以被量**。
2. **入口侧第一次被量了**：`scripts/evaluate_entry_path.py` 在 2025-01 → 2026-09 上给出主题门的
   分离读数（264,420 板块-日）：**下沿分得开、上沿没有梯度**，量级小到可能是噪声。
   这是**初步读数、不是结论**。
3. **有一个 T+1 日频提案正在评审**
   （`docs/exec-plans/active/2026-09-16-the-agent-decides-each-morning.md`）：
   把主模式从盘中改成日频，让历史可回放。它自己写明**「加速的是学习与候选筛选，不是晋升」**——
   因为 `paired_count` 的 `s.date > frozen_at` 让历史永远替代不了前向证据。

## 5. 我们答不了的六个问题（按我们认为的重要性排序）

**希望看到反对意见，不是确认。**

1. **抽象层面：Thesis 是不是正确的切法？** 把仓位定义成「为一个可证伪主张而持有」，
   用封闭词表的失效条件判定结束——这是不是把一个连续的、模糊的交易决策**过度离散化**了？
   真实交易员的退出往往说不出是哪条具体条件触发的。
2. **闭环层面：我们在给正确的东西打分吗？** 现在打分的对象是「概率准不准（Brier）」
   +「理由的信息量」+「说的和做的一致吗」+「盲点率」。**有没有漏掉更重要的维度？**
   尤其：那 94 笔**从未成交**的决定该不该进校准？一个从没成交的判断，是判断错了、
   定价错了，还是根本不该被算作一次判断？
3. **样本效率：在这个数据量下，「学习」可能吗？** 一天 1–2 笔，一年 250 个交易日。
   要在多少个已结论点之后，校准曲线才算有信息？如果答案是「几百笔」，那这个项目的
   时间尺度是**几年**。**有没有办法把学习信号的密度提上去，而不失真？**
   （我们想过一个方向：对被取消的订单做**反事实重放**——如果当时成交了会怎样。
   日线数据足够，但那是在用一个**未发生**的世界训练。）
4. **边界层面：那条原则站得住吗？**「代码承担已验证的判断 + 不可逆风险边界，
   agent 承担还没答案的判断，移交过程就是 Evolve」——这是一条**真原则**，
   还是一句听起来对的话？**怎么判断一个判断「已经被验证」？**
   我们目前没有任何自动化的移交机制，全靠人看着办。
5. **成本层面：单日 425 万 token 换 0 笔成交，合理吗？** 输入输出比 20:1。
   这是「思考很贵」的正常代价，还是**架构在反复递送它本该记住的东西**？
6. **最根本的：这条路本身。** 如果你认为「用 LLM 养一个会进化的短线交易员」在 A 股短线
   这个信噪比下**根本不成立**，请直说，并说明**在什么条件下它会成立**。
   我们更怕花两年做一个永远学不会的东西，而不是被否掉。

## 6. 一个具体的、有代表性的失败（读完上面再看这个）

2026-09-10 上午，标的 301511：

- 盘中异动扫描把它推上来 **19 次**
- 定价 agent 看了 **19 次**，否了 **19 次**
- 19 次的理由**几乎是同一句话**
- 产出：**0**

它每一次都有完整的决定权。**缺的是记忆，不是自由。**

这既是一个 bug，也是这个项目的一个隐喻：**一个不记得自己想过什么的系统，
看起来在思考，实际上在原地重启。** 我们最想被评审的，就是**系统里还有多少地方是这样**。

## 7. 已知的坑（评审者自己也会踩，先说明）

1. **文档分「规范」「状态」「研究输入」「归档」四类，角色比日期重要。** 一份规范文档描述
   「目标态」而不描述「已建成」；一份状态文档**一旦落后于代码就是错的**。分不清这两类，
   会把蓝图当交付。`docs/README.md` 是权威地图。
2. **「已交付」不等于「在跑」。** 这个项目里这两句话被刻意分开：
   Phase 4 的机制已交付，但**一次真实晋升都没发生过**。别把前者读成后者。
3. **文档里的测量数字带日期，不要当常量。** 例如 `QUALITY_SCORE.md` 的每个 Gap 现在都标了
   测量日期，因为它们会被后续动作改变——**这也是我们这周修过的缺陷**。
4. **`exec-plans/active/` 里的计划是提案，不是承诺。** 它们的验收标准是「跑 X 输出 Y」，
   有些**尚未开始**。看复选框就知道走到哪了。
