# The agent decides each morning, and history can replay it

状态：active（**提案 · 未实现**）
创建：2026-09-16

## 目标

把主模式从**盘中**改成**T+1 日频**：每个交易日**开盘前**，agent 只读「当时已存在」的信息
（T+0 及更早的日线 + T+1 09:00 之前的新闻），做一次分析，然后**为 T+1 下单**
（下单价、笔数、何时卖）。这样任何 2020-01 → 今的窗口都能被**逐日走前重放**，
把「等几周才攒到二十个配对样本」换成「一晚上跑完几年」。

## 为什么这个方向对

1. **没有分钟数据 ⇒ 盘中决策不可回放。** 这一条不可绕过：`daily_kline` 是日线；
   盘中的 `intraday_signal` 预测是实时监控产出的，要重放它得知道当天的分钟路径——我们没有。
2. **前向太慢。** 门槛 20 个配对样本，慢账本（`morning`）约 2.7 条/日。
3. **新闻历史已经有了**：`财联社电报(历史回填)` **935,850 条**，2020-01-01 → 2026-09-15，
   与价格窗口精确重合。
4. **这条路已经被走过一次**：`scripts/replay_evolution.py` 逐日 `with replay_as_of(d):`
   生成候选 → VPA 打分 → 存预测 → 次日验证 → LLM 复盘 → `post_review` 提炼教训。
   它是概念验证，但有三个缺口（见「缺什么」）。而且 `fund_flow` / `market_breadth` /
   `anomaly_detect` / `web_search` 这四个工具**已经尊重回放时钟**，底座是现成的。

## 一条硬约束：这加速的是**学习**，不是**晋升**

`paired_count` 的 SQL 里有 `AND s.date > <version.frozen_at>`，设计 §11/§12 也写明
*"Historical replay is development evidence"*。所以：

- ✅ 快速迭代策略、快速积累「什么条件下有效」的样本、**快速筛掉坏候选**
- ❌ **不能**代替那 20 个前向配对样本

这不是缺陷，是**正确分工**：**用历史筛候选，把前向窗口花在活下来的候选上。**
（把这条放在最前面，是因为「跑几年历史就能晋升」是最容易犯、也最贵的误读。）

## 泄漏边界 —— 你问的那个「是吧」，答案分三层

核心判据一句话：**决策只能读决策时点之前存在的信息；之后的行情只能进成交引擎，不能回喂决策。**

| 字段 | 决策可读 | 说明 |
|---|---|---|
| T+0 及更早的日线 | ✅ | 截至昨收 |
| T+1 09:00 之前的新闻 | ✅ | 走 `read_news(as_of=...)`，它按 `published_at` 切 |
| **T+1 的开盘价** | ⚠️ **有条件** | **订单是「市价开盘」时无所谓**（成交价本来就等于开盘）；若让 agent 先看开盘再挑限价，那就是偷看 |
| T+1 的成交量 | ❌ 决策 / ✅ 引擎 | 引擎用它做容量上限（不能买超过当日量的一定比例）。**「只给引擎」不等于「它对决策没用」**——它会经成交与否间接影响结果，这是正确的 |
| T+1 开到收的全路径 | ❌ | 只用于判定限价是否成交、是否触发止损/到期 |
| T+1 的涨跌停价、是否停牌 | ✅ | 这些是**规则**（昨收×1.1 / 标的属性），不是结果 |
| 财报、公告 | ✅ 但必须用**公告时刻** | 不能用报告期。用错这个是最隐蔽的前视 |

⇒ **开盘价本身不是泄漏，「先看开盘再决定」才是。** 所以把这件事交给价格类型去保证：
M1 只支持两种订单——**市价开盘**（不看任何 T+1 价格）与**限价**（价格由 T+0 及更早决定）。

## T+1 规则（不建模就是在骗自己）

1. **可卖数量 = 昨收持仓。** 今日买入的不可卖 —— 因此「做 T」的合法形态是：卖掉昨天的仓、
   当天买回，买回的部分明天才能卖。**不是**「先买后卖」。
2. **涨跌停**：`limit = 昨收 × (1 ± pct)`。**开盘即涨停 ⇒ 买单不成交**；
   这条不建模会让回测虚高最多（A 股最想买的那只往往一字板）。
3. **停牌**：当日无 K 线 ⇒ 不可交易，持仓冻结、估值沿用上一有效价。
4. **卖出同样是 T+1 的下一日**，规则同上。

## 架构：驱动**同一个**内核，不写第二个回测器

设计不变量是「一条执行路径」。仓库已有 `virtual_portfolio` / `reservations` /
`settlement` / `intent.submit_intent` / `order_state.assert_transition`，而且都有测试。
所以走前回放应当是**用 `replay_as_of` 驱动这些既有模块**，而不是另写一个撮合器——
后者会和内核慢慢分叉，然后没人知道哪个是对的。

`replay_evolution.py` 现在**只存预测、不落订单**（它 import 的是 `save_prediction` 那一族），
所以「接上内核」正是它要往前走的一步。

## 缺什么（按必须先后来排）

1. **`DATA_DIR` 不可覆盖 —— 这是第一件必须修的。** `config.py` 里
   `DATA_DIR = PROJECT_ROOT / "data"` 是硬编码，没有环境变量出口。
   后果具体且严重：走前回放会**写进生产库**，污染实盘账本、预测表、教训表——
   也就是污染系统赖以判断自己的那份证据。修法：加 `ALPHAAGENTS_DATA_DIR` 覆盖 + 一条测试。
2. **没有「一天一个决策」的任务**：现有 `morning_scan` 产出的是成批预测，不是
   「下单 + 管持仓 + 决定何时卖」的循环。
3. **没有 T+1 撮合**：开盘价成交、涨跌停、停牌、做 T 的可卖量。
4. **新闻还没进决策**：现有候选来自「资金流 top sectors × 板块内低涨幅高流动性个股」，
   和新闻无关。
5. **CLS 付费栏目不可回放**（已记录）：重建语料只有免费快讯流，结论只能声称快讯流的效果。
6. **`theme_score` 的 `strength` 没有历史**：绝对阈值在回放里不可用（排序仍然忠实）。

## 里程碑

**M1 — 最小可跑。** 修 `DATA_DIR` 覆盖 → 从生产库**分叉**出一份 `data/walk/` →
用 T+1 撮合跑通「一天一个决策」，30 个交易日，产出 equity curve 与成交明细。
- [ ] `ALPHAAGENTS_DATA_DIR=/tmp/walk .venv/bin/python scripts/walk_forward.py --start … --end …`
      → 退出码 0，且**生产库文件 hash 在跑前跑后不变**
- [ ] 同一窗口连跑两次，成交明细逐行相同（确定性；LLM 部分除外，见风险 4）
- [ ] 开盘一字涨停的标的**没有**出现在成交里；停牌标的没有成交
- [ ] `tests/` 覆盖三件：可卖量 = 昨收持仓、涨跌停拒单、停牌冻结

**M2 — 接新闻。** 把 `read_news(as_of="T+1 09:00")` 折成信号。**先做「只当过滤器」那条**：
只保留当天被提及的板块/个股，看同样的规则分离是否变好。产出「有新闻 / 无新闻」两份走前结果对照。

**M3 — 接学习与演化。** 把 `post_review` 的 lessons / principles 也放进分叉库；
在历史上跑完整闭环，用它**筛掉坏候选**，只把活下来的送进前向影子实验。

## 决策记录

- **为什么 T+1 而不是盘中**：没有分钟数据，盘中不可回放。不可绕过。
- **为什么驱动同一个内核**：设计不变量「一条执行路径」；而且撮合逻辑已写好且被测过。
- **为什么先修 `DATA_DIR`**：不修，第一次跑就把实盘账本写了。
- **待确认的一处读法**：你的描述里 agent 是「看新闻 + 历史数据 → 直接选股下单」，
  这条路**不经过**现有的主线门（`theme_gate`）与「可证伪论点」机制。两种读法：
  (a) 新增一个**平行的 T+1 模式**，现有盘中链不动；(b) 用 T+1 模式**替代**盘中成为主模式。
  这两条的迁移成本差很多，**请你定**，我先按 (a) 写，因为它不破坏现有闭环。

## 风险

- **回测漂亮、前向平庸 —— 这是最大的风险。** 走前回放最大的诱惑就是过拟合。
  **信号**：M2 若在历史上分离很强（例如 Q5−Q1 > 1%），**先怀疑泄漏与前视，再高兴**。
  这也是为什么历史只用来**筛候选**、不用来晋升。
- **分叉库漂移**：分叉之后生产库继续前进，两边 schema 会分叉。
  **缓解**：分叉时把源库的 schema 指纹记下来。
- **付费栏目缺口**：见「缺什么」第 5 条。
- **LLM 不可复现**：走前每跑一次都会产生**新的**判断，所以结果不可逐字复现。
  **缓解**：不要指望种子；应当把**决策输入快照**落盘，这样「同一次判断」才可被复查。
  （这与之前记过的「从今天起落盘」是同一件事，现在它不再是可选项。）
- **`replay_evolution.py` 会写生产库**：在 M1 落地之前，**不要再跑它**。
