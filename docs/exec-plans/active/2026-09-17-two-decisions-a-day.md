# 一天两次决策，各自看到各自能看到的

状态：completed（四象限全部落地；三个缺陷已修）
创建：2026-09-17

## 目标

把回放的一天从「一次决策」改成**两次**，并且**每一次只能看到那个时刻真实
能看到的东西**。同时修正一个已经存在的前视缺陷。

## 用户提出的模型（原话）

> 开盘跌停和涨停也是买不进去 或者卖不出去的，每天应该是两次，开盘卖出/
> 买入还是收盘卖出/买入，前者只能看到开盘价格，后者可以看到开盘价，收盘价，
> 最高最低，成交量，假设收盘前我们看到的基本等于这个数据即可，即使滑点也很小，
> 可以忽略。

拆成四条：

1. **开盘时刻**：只能看到 **T-1 收盘 + T 日开盘价**。今天的最高/最低/收盘/
   成交量都还不知道。
2. **收盘时刻**：可以看到 **T 日全部 OHLCV**（开盘、最高、最低、收盘、成交量）。
   "收盘前看到的约等于收盘数据"——所以收盘决策按 T 日收盘价成交，滑点忽略。
3. **涨跌停两个方向都要挡**：开盘涨停买不进、开盘跌停卖不出（这条已实现）；
   收盘同理：收盘涨停买不进、收盘跌停卖不出。
4. **一天两次**，不是一次。

## 已核实：开盘的涨跌停**已经**挡了

`t1_execution.market_on_open` 对两个方向都拒绝：

```python
if side == "buy" and _reaches_up(bar.open, prev_close * (1 + limit_pct)):
    return Fill(NO_FILL, None, "open is the up limit — no counterparty for a buy")
if side == "sell" and _reaches_down(bar.open, prev_close * (1 - limit_pct)):
    return Fill(NO_FILL, None, "open is the down limit — no counterparty for a sell")
```

买入走 `entry_verdict`（先问 `market_on_open(side="buy")`），卖出走
`exit_verdict`（先问 `side="sell"`）。所以**第 3 条的开盘部分不需要新代码**。

## 已核实：一个真实的**前视**缺陷（本轮必须修）

`_agent_exits` 用**昨天的收盘价**给 agent 看持仓，然后 `apply()` **直接拿这个
价格平仓**：

```
600186  决策日 08-20 09:35
        成交价 11.61  ← 这是 08-19 的收盘
        而 08-20 实际开盘 11.56
```

也就是说：**它用昨天的价格卖掉今天的仓位**，白拿一天信息。真钱里 09:35 的
卖出只能以今天开盘价（或当时市价）成交。

**为什么之前没发现**：`price_map` 同时承担两个职责——「给 agent 看它现在值多少」
和「成交价」。第一个用 T-1 收盘是对的（09:00 决策时最近的价格就是它），
第二个用 T-1 收盘是前视。两个职责必须分开。

## 设计

### 两个决策时刻

| 时刻 | 能看到 | 能做什么 | 成交价 |
|---|---|---|---|
| **开盘** `09:00` | T-1 收盘 + **T 开盘** | 买/卖 | T 开盘 |
| **收盘** `14:55` | T 全量 OHLCV | 买/卖 | T 收盘 |

**为什么用 `14:55` 而不是 `15:00`**：用户说"收盘前看到的基本等于这个数据"。
`14:55` 这个标记让 `replay_as_of` 的语义诚实——它是决策时刻，不是收盘时刻；
而成交价按用户指示用 T 收盘。

### 关键：把「看」和「成交」分开

`_agent_exits` 拆成两个参数：
- `mark_map`：给 agent 看的价格（开盘时刻 = T-1 收盘；收盘时刻 = T 收盘）
- `fill_map`：成交价（开盘时刻 = **T 开盘**；收盘时刻 = T 收盘）

**这是本 plan 的核心修正。** 现在两者是同一个 map，这就是前视的来源。

### 涨跌停（新增收盘侧）

收盘成交也要问涨跌停。`market_on_open` 是开盘专用，需要一个收盘版本或者
一个通用的 `market_at(price, side, ...)`。**注意**：收盘涨停时是**买不进**
（没有卖盘），收盘跌停时**卖不出**——方向不能写反。

## 验收

1. `tests/test_two_decisions.py`
   - 开盘时刻的 prompt 里**不含** T 日的最高/最低/收盘/成交量
   - 收盘时刻的 prompt 里**含** T 日 OHLCV
   - 一天**两次**模型调用（开盘 + 收盘），不是一次
2. **前视回归测试**：agent 在 T 日卖出，成交价必须是 **T 日开盘价**，
   **不等于** T-1 收盘价（用 600186 那个真实案例做 fixture）。
3. 涨跌停四象限，每个都有测试：
   - 开盘涨停 + 买 → 不成交
   - 开盘跌停 + 卖 → 不成交
   - **收盘涨停 + 买 → 不成交**（新增）
   - **收盘跌停 + 卖 → 不成交**（新增）
4. 一个反向测试：开盘涨停 + **卖** → 应当成交（涨停时卖得掉），
   开盘跌停 + **买** → 应当成交（跌停时买得到）。**不写这两条的话，
   一个"两边全挡"的粗暴实现会通过上面四条。**

### 修掉的三个缺陷

**1. 前视：卖出用的是昨天的价格**（本轮最重要）

`_agent_exits` 用一个 `price_map` 同时做两件事——给 agent 看持仓值多少、
以及成交价——两者都是 T-1 收盘。实测：

```
600186  决策日 08-20，成交 11.61 = 08-19 收盘
        而 08-20 实际开盘 11.56
```

**用昨天的价格卖掉今天的仓位**，白拿一天信息。现在拆成 `mark_map`（看到
什么）和 `fill_map`（以什么成交）。

**2. 收盘决策的面板排名日错了**

`_decide_llm` 对两个时刻都传 `prev_day` 作排名日，而 `_close_buys` 用 `day`
重建面板核对——两者不一致，导致 20 天里**每一次收盘买入都被计为
`close_buy_not_offerable`，一笔没成交**。排名日现在跟时刻走。

**3. 「一只票只能有一笔」没告诉 agent**

`portfolio` 会拒绝同一只票的第二笔持仓，而拒绝信息列了四种可能原因，读起来
和"题材不合格"没区别。实测收盘决策重复买入当天早上已买的 `603407` 和
`300035`，11 笔被拒。规则本身是对的，所以**是补提示词，不是放松规则**。

### 收盘买入的三个设计决定（各有测试）

- **建仓而非挂单**：挂单会在**下一个开盘**成交，而那正是这个决策拿不到的价。
- **先过涨停检查**：复用收盘卖出用的同一个 `market_at_close`。
- **仍尊重 `entry_low`/`entry_high`**：读作"愿意接受的区间"而非挂单价。
  区间外成交等于系统替交易员接受了他拒绝的价格。

## 明确不做

- **不改生产**。`exit_decision.run` 与 `position_monitor` 是生产路径，不动。
- **不引入滑点模型**。用户明确说可以忽略。
- **不改 T+1**。当天买入仍不能当天卖出。
