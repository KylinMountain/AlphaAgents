## 1. 目标与权威关系

把当前“模块已有、调用与测量未闭合”的 Sector-First，修成可运行、可追溯、可归因的最小实验链。完成后，工程上能回答为何选、为何买、为何拒绝、承担什么风险以及哪一项改变导致差异；策略是否有效仍由之后的预注册实验回答。

本计划是本轮整改的**开工入口与任务状态来源**。原 [2026-09-19 Sector-First 计划](2026-09-19-sector-first-opportunity-selection.md) 保留目标设计和历史实施记录；其中“基础设施基本就绪”的表述不能覆盖本次发现的 P0。全局阶段仍以 [Trader Core Design](../../TRADER_CORE_DESIGN.md) §14 为准。

审查 F01–F14 与本计划 RP-00–RP-11 一一映射。审查是固定日期的证据记录；任务完成后更新本计划、实现状态和旧路线图，不改写历史报告使缺陷看起来从未存在。

### 1.1 本轮不做什么

不换默认 `dual_rank_v0`，不移动 active policy，不接真实券商，不购买/扩张数据权限；不训练模型、不新增专家投票团队、不自动调参、不同时改多种买卖形态，不重写账本或新增第二套撮合器。

本次文档提交只落报告、计划、复现附件和导航。后续每个工程包独立交付；不能把“用户批准写计划”当成“批准新策略晋升”。

### 1.2 责任与协作

- **工程 Leader / 单一主审：**确定任务顺序、控制范围，按证据验收；不得仅依据执行者的完成声明勾选。
- **主执行工程师：**同一工作树同一时间只有一个写入者；先复现再改，实现、测试和文档一起提交。需要并行时用独立分支，先明确不重叠的文件所有权。
- **仓库 owner：**批准会改变资金风险、交易策略或实验问题的取舍；生产批准独立于代码与测试验收，Agent 不得自签。

此处定义工作职责，没有创建或启动任何后台 Agent。所有任务状态从 TODO 开始，启动时记录实际负责人和 commit。

### RP-02：初始账户状态与唯一绩效口径

**主要落点：**`scripts/walk_forward.py`、`alpha_agents/evolution/sector_experiment_compare.py`、`tests/test_sector_experiment_compare.py`。

**实现：**在任何决策/费用/成交前冻结初始账户状态；显式标识 initial mark。收益、回撤、日收益、文字摘要和 comparison 复用同一个计算接口。完整验证日期与数字，不再把空值自动视为零；禁止隐式字典覆盖重复日期。

**验收：**
- [ ] 初始 100→95→100：净收益 0%、最大回撤 5%，两天收益为 -5% 与约 5.2631579%，误差不超过 1e-8；initial mark 不增加交易日数。

**主要落点：**现有 direction/stock selector、planner prompt、Opportunity Journal 与 `scripts/walk_forward.py` 的装配；逐步让 morning/T1 使用同一关系和资格校验。新增类型放在允许的共享层，不在脚本里复制业务规则。

**目标契约（待实现，不是已存在文件）：**一个版本化 research packet，包含 decision/world/policy 引用、cutoff、方向 thesis、主/辅主题关系证据、股票横向比较、实际读取事实及来源、反证、未知项、期限、失效条件、预算使用和阶段状态。可用但未读与实际读取分开。

**实现：**研究事实一旦生成就显式传给下一阶段，不能只留下股票/主题 ID。planner 只能在 packet 事实范围内定计划；缺必需价格依据时返回结构化拒绝。主 thesis 不以 round-robin 遍历先后自动伪装成经济论点；旧归因迁移需保留原记录。

**验收：**
- [ ] 固定 fixture 中，上游获取的 ATR/结构/事件反证及引用原样出现在 planner 输入，hash 和 cutoff 可验证；过期/未来/不匹配引用被拒。

### RP-05：实验协议重构——不要一次问三个问题

**主要落点：**`alpha_agents/evolution/sector_experiment.py`、comparator、runner；新协议使用新版本/新家族，不改写已注册 manifest，也不重命名旧 A/B/C/D 的含义。

**先固定的研究定义：**

| 比较 | 固定项 | 唯一有意变化 | 不得声称 |
| --- | --- | --- | --- |
| 原 incumbent vs 新完整系统 | 同一评估期间与已说明约束 | 系统总体设计 | 差异完全来自板块优先 |
| NF-DUAL vs NF-SECTOR-RULE（首个最小实验，名称待实现） | 全流程 no-flow、共同 PIT 世界、共同选股规则/planner/执行/退出/学习输入 | 双榜发现 vs 透明方向发现 | 已证明资金流或 LLM 增量 |
| NF-SECTOR-RULE vs NF-SECTOR-LLM-DIR | 相同世界、板块内处理和下游 | 方向解释/选择 | 已证明 LLM 个股选择能力 |
| 冻结方向下的 RULE vs LLM-STOCK | 同一方向、候选、微观比较账户与共同下游 | 个股选择方法 | 单次选择增量等于完整账户增量 |

**实现：**支持明确命名的实验家族和比较对；不以“必须有四臂”阻塞只问一个问题的合规新协议。全链 no-flow 覆盖方向、股票卡、工具可见字段、知识及新闻材料，使用输入白名单和特征依赖，不只删几个标题关键词。发现无法证明隐藏的通道，则标不支持该消融。纯数字/价格最小实验可先不向模型提供未审计的自由新闻正文。

**主指标选择：**首个最小实验采用固定评价期限内、扣费后的组合净收益差，单位明确为 percentage points；若用 block bootstrap，重采样配对收益路径并重算相同期限统计量。日均差另列诊断，不与主指标共用阈值。风险否决独立于收益 CI，不得因为较高收益覆盖越界。

**验收：**
- [ ] 协议闭集校验 metric、单位、比较方向、supported capability、期限、风险边界、停止规则；不接受任意非空字符串假装支持。
- [ ] 第一轮冻结可进入决策的学习/经验输入；_learn 可写隔离观察，但不回灌该固定策略实验。自适应比较另开版本。
- [ ] 原始 incumbent 不变；bug-fixed baseline 与 cleaned counterfactual 有不同身份，结果不能跨身份比较。
- [ ] 4×30 日的每窗只出诊断，总体按预注册规则汇总 120 个唯一日；不能让单窗 minimum_days=50 永久阻塞，也不能通过降门槛解决。
- [ ] 明确窗口是连续持仓还是独立重置账户；汇总不得跨重置边界制造收益，block 不越未允许的边界。
- [ ] 训练标签按最大期限 purge/embargo；所有正式结果都记录 label cutoff、未成熟与缺失处理。
- [ ] 各臂请求、重复次数、技术重试/无效样本规则事前冻结；失败与零行为改动也存档，不挑好看的重跑。

未取得可用真实数据和冻结数值前，只能跑 synthetic fixture；不得自动填“最优风险阈值”启动正式实验。

### RP-06：真实内部 E2E、产物构建与结果封存

**主要落点：**`scripts/sector_first.py`、现有 direction/stock outcome、Dream 报告 CLI 与 comparator；CLI 只组装，不复制领域实现。

## 5. 提交、测试与状态纪律

每个 RP 可以分几个小 PR，但一个 PR 只有一个主要验收目标。先写能在旧代码上失败的真实回归，再实现，再跑相关测试及全量；禁止新加 skip/xfail、扩大异常吞没或放宽门槛让测试变绿。单元测试、真实内部 E2E、正式数据实验、前向策略结果分别报告，不用数量混算。

每个 PR 的说明必须包含：关联 F/RP、前后行为、改动文件、明确不做项、测试命令与实际输出、数据/策略状态、回退方法。使用 `KylinMountain` 个人连接；禁止 force push。

基本验证命令：

```bash
uv run pytest tests/ -q
uv run python scripts/lint_harness.py
uv run python scripts/lint_docs.py
uv run python scripts/lint_policy.py
```

补充 E2E 可放在现有测试体系；新 CLI/测试文件创建之前，计划中的名称只表示拟议接口。CI 未完成不能写“全部通过”，旧 commit 的成功不能证明新 commit。基线已有失败记录原因和影响，不掩盖、不虚报。

状态只允许：TODO → IN_PROGRESS → IN_REVIEW → DONE，或 BLOCKED（写明缺什么证据/数据/决策）。DONE 必须有已合入 commit 与测试证据；“已写文档”“已提交 PR”“代码已合入”“策略已验证”分别陈述。

## 6. 风险与回退

| 风险 | 控制与回退 |
| --- | --- |
| 修基线改变对照身份 | 保存原 baseline；fixed/cleaned 版本另命名、另 hash；旧结果不覆盖 |
| 类型/Journal 扩展破坏旧记录 | 版本化、向后可读或显式 legacy_unknown；不事后补有利论点 |
| 修量化指标后历史报告不可比 | 旧报告保留 metric version；重算生成新产物，不原地改写 |
| 新风险门减少成交导致误读 | 把拒绝原因与成交不足单列，不把少交易自动当选股更好 |
| no-flow 残留文本通道 | 输入白名单/来源声明，无法证明则不支持该消融 |
| 拆分脚本产生反向依赖 | 沿现有层级和共享入口迁移，lint 通过；不新建重复 kernel |
| 过早启动带成本实验 | preflight 先运行，未冻结权限/参数不调用真实模型或付费来源 |
| 前向记录被误用为晋升 | observation_only 与 candidate-forward 分域；注册时间与证据不可回填 |

代码问题采用正常 revert/new commit 回退，不 force push；不删除订单、快照、失败候选或审查证据。功能开关只影响未来决策，已有仓位仍由原内核管理。
