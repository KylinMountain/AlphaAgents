# 买多少、买几只，交给 agent；组合包络交给闸门

2026-09-22。用户：「不需要平均仓位3.2的限制。。。每天最多2单也没有必要，
size pct 都不应该限制，而是让其自行演化 自行决定」。

## 先纠正一个事实

**「平均仓位 3.2%」不是一条限制**，是 20 天回放量出来的结果，代码里没有
这个数。它是 `picks=2 × size 3–8% × 成交率` 的算术后果。要动的是产生它
的那几条。

## 现存的限制，以及哪条真的咬住

| 限制 | 值 | 位置 | 咬住了吗 |
|---|---|---|---|
| 每日单数 | 2 | 提示词 ×4 + `sector_stock_selector.py:101` 解析截断 | **是，最硬** |
| size_pct 界 | 0.5%–50%，**超界丢弃** | `t1_decider.py:_THESIS_BOUNDS` | 是（丢弃后回落 3%） |
| 单票上限 | 10% / 12% | `traders/*.yaml: max_position_pct` | 边缘 |
| 默认仓位 | 3% / 4% | `traders/*.yaml: default_size_pct` | 是（被丢弃时） |
| 总暴露 | 40%（修复相位） | `sentiment_cycle.py` | **否**（实际 3.2%） |
| 现金 / T+1 | — | `reservations` | 是 |

`picks` 有两层：提示词说「最多 {picks} 单」，解析器再截断一次，多选的
标记 `too_many` 丢弃。**agent 就算想多买也进不去。**

## 做什么

1. **每日单数不再是数字。** 提示词不再给 N，改为告诉它真实约束：可用
   现金、已有持仓、集中度是它自己的判断。解析器停止截断。
2. **`size_pct` 照它说的办。** 去掉上界与「超界丢弃」。下界保留一个
   大于 0 的值，因为 0% 的订单不是订单。
3. **`max_position_pct` 不再是人写在 yaml 里的硬顶。**
4. **`default_size_pct` 只在 agent 什么都没说时兜底**（现状即如此），
   不再是「它说了但被丢弃」时的替身。

## 组合包络：不删，改成会演化的

删光之后，一次决策可以把整本账押在一只票上。反对的理由不是风控偏好，
是**学习闭环需要账户活到 n≥50 笔**——第 3 天打光，实验就结束了，而
「会因亏钱而改变行为」对没有第二次机会的交易员不成立。

但这**不支持**把数字写死在 yaml。它支持把包络变成 `policy_registry`
里的一个**版本**，由 `holdout_gate` 依市场数据移动，全程无人——
`scoring.py` 对 `DEFAULT_DECISION_PARAMS` 的注释已经写明这类参数是
"a seed to be re-fit once enough Brier history exists"，仓位参数属于
同一个地方。这才是「自行演化」，区别于「没有限制」。

**唯一保留的硬约束是现金与 T+1**：那是市场事实，不是政策。

## 验收标准

1. 一次 `--autonomous` 回放里，单日下单数 **> 2** 至少出现一次；
   `too_many` 丢弃为 **0**。
2. 至少一笔 `size_pct` **> 0.10**（旧的单票上限）落进 Thesis 并被执行。
3. 平均仓位（`market_value/equity`）相比 3.2% **上升**；空仓天数下降。
4. 包络参数出现在 `policy_registry` 的版本里，不在 `traders/*.yaml`。
5. `uv run pytest tests/ -q` 全绿；两个 lint 通过。

## 决策日志

- 2026-09-22 单笔尺寸全权交给 agent；组合包络进政策版本而非删除。
  理由：删除得到的是「无限制」，进版本得到的是「会学的限制」，
  用户要的是后者。
