# 让实验每天自己跑，并在生产库建立指针

状态：**已交付（2026-09-14）**。负责人：本次开发会话。创建：2026-09-14。

**收口要点**：判据 1–9 全部落地。`tests/test_shadow_run_task.py` 10 个用例；
全量 **1905 passed, 18 skipped**；`lint_harness` **158 文件**（新增本模块）。
生产库已建立指针（V1 在效、在效参数 == 代码默认 ⇒ 行为中性），
副本上的闸门旧 schema 已提前验证可迁移。**仍然没有 promote，也没有开第一条 run。**

> 范围：把影子实验的两个日常动作接上调度；并在生产库执行第 0 步（freeze + install）。
> 不改任何决策路径、不改评分、不改闸门判据。
> 前一支切片（[操作面](2026-09-14-evolution-operator-surface.md)）交付的是「人**能**跑」，
> 本支交付的是「它**会自己**跑」。

## 目标

到 09-14 早上为止，这条链仍然只能由人推：`emit_for_date` 的调用者只有测试，
所以一天不敲命令就一天没有配对样本 —— 而配对样本是**唯一**能让闸门开口的东西。
一套要靠人记得每天推一次的实验，在时间轴上等于零。

本切片做两件事，它们是同一个决定的两半：**开始计时**。

1. `alpha_agents/pipeline/tasks/shadow_run.py` + `main.py` 的
   `Task("shadow_run", ..., dtime(15, 45))`：交易日 15:45，排在 15:30 的 review 之后，
   对每条开启的 run 写挑战者当天的预测，再给窗口已收口的预测补分数。
2. 生产库执行 `freeze` + `install`（用户明确选择）：指针建立，V1 在效。

## 判据（机器可验收）

1. 任务在没有任何开启 run 时**返回 None 且不抛异常**，并记一条 info 说明
   「没有实验在跑」——静默的 no-op 与坏掉的任务长得一样。
2. 有开启 run 时，它按冠军当天的选股写预测，且用的是**该 run 绑定版本**的参数。
3. 面板为空时**报出来**（「没有可配对的面板」），不把「什么都没写」当成安静的一天。
4. 评分分别报出「已评分 / 窗口未收 / 已删失」（与 D10 同刀）。
5. 报告带上每条实验的 `配对进度 paired/needed`。
6. **它不调用闸门**：跑完之后 `gate_decisions` 仍为空，指针不动。
   这是判据不是偏好 —— 每天问一次会在配对天数填满前天天写一行 `insufficient`。
7. 影子层炸了**不能带走交易日**：`runs` / `emit_for_date` / `coverage` 各自抛异常时，
   任务要么返回 None，要么仍然返回一份带「失败」字样的报告，不向上抛。
8. 生产库：`status` 报 `in force: version #1 at seq 1`、`live configuration still matches: True`、
   `integrity: clean`，且**在效参数与 `DEFAULT_DECISION_PARAMS` 逐值相同**（行为中性）。
9. 全量 `pytest` / `lint_harness` / `lint_docs` / `check:render` 全绿。

## 决策日志

**D1 —— 排在 15:45，在 15:30 的 review 之后。**
面板是冠军**当天**的选股，15:30 之前 intraday 还在写、review 也还没把当天到期的
冠军预测评掉。晚 15 分钟拿到的是一份最终面板；而**对挑战者的信息量是零增量** ——
它的概率是「冠军记录下来的信心标签 × 该版本的映射」，不看价格，所以 15:45 写下的
就是冠军早上那个信号所蕴含的那一条。

**D2 —— 每天只 emit + score，不问闸门。**
这是本切片最容易顺手做错的一步。旧的 `lessons.post_review` 就是每天调
`run_gate("daily_playbook", today, today)`，结果是 3 行全部 `validation_days: 0` 的
abstain —— 一个永远触发不了的闸门比没有闸门更糟，因为它看起来像治理。
今天若每天问一次，同样会写一堆几乎一样的 `insufficient`。所以：**报告进度**，
把「该问了」的判断留给看见 `pair_ready` 的人。

**D3 —— 任务永不抛出。**
影子分支不交易，它的故障不该带走复盘。每一步 `try/except` 降级成 warning 并继续，
但**报告里要留下痕迹**（「写入失败」「评分：失败」）—— 降级成 warning 而报告里看不出来，
是「静默吞异常」的另一种写法。

**D4 —— 生产库的 freeze / install 由人决定，且先 dry-run。**
`install` 是单向的（没有 uninstall，之后改映射必须走 ≥20 个配对交易日的证据路径），
所以这一步是操作决定而不是实现决定。执行前先 `--dry-run` 打出内容哈希，
执行后用 `status` 复核「在效参数 == 代码默认」，把「行为中性」当作可验证的断言而不是说法。

**D5 —— 把「旧 schema 的闸门表」提前验证掉。**
生产 `gate_decisions` 缺四列，而 20 个交易日后 `gate` 要往那四列写。
在**副本**上跑一次 `record_gate_decision` 确认 `_ensure_gate_table` 的 `ALTER TABLE`
会补齐并写成功；**没有**在生产库写任何裁决行。

## 不做的事（本切片不做，别当待办）

- **不开第一条影子 run。** 它需要先回答「第一个候选测什么」，而且开一条 run
  会开始累积一条不可回退的实验记录。调度装上之后，开 run 仍是人的动作。
- **不把 `run_gate` 挂上调度**（D2）。
- **不迁移生产库的其它旧 schema**（`learning_candidates` 缺列、
  `candidate_transitions` 整表不在）。那是运维动作，且与本切片无关。

## 风险

- **15:45 这个时间点是相对 15:30 的 review 定的**：如果 review 因 `catch_up_grace_minutes=90`
  拖到 16:00 之后，emit 会在面板还没最终化时跑。当前 intraday 在 15:00 停、
  morning 在 09:00 写完，所以即使 review 延后，**面板本身**也已经是最终的 ——
  受影响的是冠军的评分（那影响的是几天后的闸门，不影响 emit）。
- **任务只在交易日跑**（`Task` 默认 `trading_day_only=True`）：非交易日 emit 出来的
  面板要么空、要么是错的一天。这与 `_deadline_for` 的日历语义叠加不会互相抵消：
  日历截止日仍可能落在非交易日，那是 D10 已经处理过的那一类，由
  `evidence_window_closed` 兜底。
