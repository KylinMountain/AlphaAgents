# 多交易员：把「变异」变成一个文件

2026-09-09

## 问题

系统里的进化只有一半。`holdout_gate` 会在冠军策略和挑战者之间跑配对
检验 —— 选择那一半是有的。但挑战者从哪来？`scan_and_auto_create` 从
**已经成功的交易里**挖模式。也就是说，所有候选变异都是过去分布的产物。

只从自己的成功里学习的系统，最后会收敛到自己身上。它可以把现有打法
打磨得更好，但永远不会问「如果反过来做会怎样」。

具体到这套系统，最该被问的就是那一行：

```python
entry_low = price * 0.97   # intraday_monitor.py，改之前
```

**113 笔订单里 109 笔是这么定价的。** 剩下 4 笔来自晨扫 agent，
那 4 笔的介入价是它自己写的。

也就是说 96% 的订单**根本没有 agent 参与定价**——它们来自一个纯 Python
打分函数：函数负责选股，然后顺手把价格也定了。

而这个常数跟标的没有任何关系。实测：中钨高新日均波动 5.6%、通源石油
6.1%，给它们挂 3% 宽的区间，比一天的正常波动还窄，一天就跳过去了——
这两笔正是以「价格已涨走」撤单的。

## 设计

一个交易员 = `traders/` 下的一个 YAML 文件。

```yaml
id: breakout
name: 突破派
capital: 1000000
prompt_file: morning_scan.md
extra_prompt: |
  你追时机，不追价格。
  硬规则：你的 entry_low 不得低于现价。
  ...
```

**这里没有任何价格。** 介入价、止损、仓位全部由 agent 自己调
`get_price_levels` 算——见下面「走过的弯路」。

加一个策略不需要改代码。更重要的是：因为变异**本身就是一个有固定
schema 的文件**，复盘 agent 最终可以自己写一个出来 ——

> "25 笔挂单撤了 22 笔，13 笔死于等回调。我想试试追突破，30 万，
> 跑两周。"
> → `traders/breakout_v2.yaml` → `holdout_gate` → 保留或归档

和失效条件词表是同一个设计思路：给 agent 一套**受限但够用的语法**，
而不是任意权力。

### 走过的弯路：entry_style

第一版给配置加了个 `entry_style` 枚举（pullback / breakout / market），
理由是「提示词表达不了介入区间」。

**这个理由是错的。** 提示词表达得了，晨扫 agent 一直在自己写介入价；
那 109 笔固定 3% 的订单不是因为提示词说不出别的，而是因为**那条路径上
压根没有 agent 可问**。给常数起名叫「风格」放进配置，只是把「没有判断」
这件事包装成了一个决策，还把一个交易员能变成什么样，卡死在 Python 字典
里的三个值上。

判断标准应该是：**如果 agent 有工具能算出来，就不该写进配置。**

所以 `entry_style` 删掉了，换成两件事：

1. 新工具 `get_price_levels(code)` —— 返回均线、20/60 日区间、支撑阻力、
   日均波幅（atr_pct），**不返回任何建议**
2. 盘中路径接入定价 agent —— 打分函数只负责选股，介入价/止损/仓位交给
   agent 带工具去算

配置里剩下的是 agent 算不出来的：给了它多少钱、读哪个提示词、
不能突破的兜底上限。

### 提示词里那句谎话

顺带发现的：`morning_scan.md` 告诉 agent「`get_institutional_position`
返回介入区间和止损位」，然后紧跟一句「**不要自己编造价位**」。

那个工具没有这两个字段。所以 agent 被告知有人会给它价格，然后没人给，
还被禁止自己算。4 笔晨扫订单全是单边 `entry_high`，一次 `entry_low`
都没写过。

改完之后 agent 会自己调 `get_price_levels`。实测一次真实定价：

> **回调派对通源石油直接 skip** —— 「20日区间位置87.7%属高位，
> ATR 6.1%波动太大，介入区间难以有效匹配。等回调到10.7附近再评估。」

这是常数永远做不出的判断：旧代码会给它挂一个 3% 的单，隔天以
「价格已涨走」撤掉，然后这笔撤单还会被算进「介入质量」统计里，
让人以为是定价问题。

### 风格没被执行，会被数出来

删掉 `entry_style` 的代价是真实的：策略差异全靠提示词，而提示词**可以
被无视**。第一次实测就撞上了——突破派给出的理由是「等回调至20日低点
33.42附近获得支撑」，把单挂在了现价下方。那是回调派的逻辑。

代码里不加规则去管它（那就是 `entry_style` 换个名字回来），改成**数出来**：
`portfolio_risk.entry_side()` 统计每个交易员的挂单落在现价哪一边，
进晨扫和复盘的上下文。历史数据的分布是 **111 笔里现价上方 0 笔** ——
`price * 0.97` 的指纹一目了然。

一个交易员如果说自己追突破却有一半挂在下方，那它就没有风格，
配置文件写什么都没用；而两个分布一样的交易员，是同一个实验跑了两遍。

## 什么各自独立，什么共享

这个划分是整件事能不能测出东西的关键。

**各自独立**（否则比较无意义）：

| | 为什么 |
|---|---|
| 资金 | 两个策略从一个池子取钱，先跑的那个饿死后跑的 —— 测的是执行顺序不是水平 |
| 持仓 / 挂单 / 论点 / 预测 | 同上 |
| 校准曲线 | 两条策略混在一起的曲线描述的是一个平均值，那是**没人在跑的交易员**；更糟的是它会让准的那个照着不准的那个去修正 |
| 盲点率 / 一致性 / 决策质量 | 同上 |
| 净值曲线 / 回撤 | 因为 A 回撤而停掉正在赚钱的 B，等于让 B 的风控测量 A 的亏损 |
| 板块集中度 | 集中度是**单个账本**的属性。两个交易员都持有金属铜是实验，一个交易员用两个名字持有它才是集中 |
| 介入质量（撤单率） | 这**就是**区分回调派和突破派的那个数 |

**共享**（那是事实，不是策略）：行情、主线状态与强度、快讯、工具、
情绪周期相位、principles / playbooks / lessons。复制一遍只会让成本翻倍。

盘中周期只抓一次行情，然后按交易员循环管理各自的账本；晨扫的新闻窗口、
主线发现、事件摘要也只跑一次，只有 agent 调用和下单是每个交易员一遍。

## 数据层

三张表加了 `trader_id TEXT DEFAULT 'default'`：`virtual_portfolio`、
`theses`、`predictions`。默认值就是历史行为 —— 引入这个特性之前的
所有行都属于 `default`，单交易员部署完全看不出区别。

`predictions` 的唯一键从 `(date, code, report_type)` 变成
`(date, code, report_type, trader_id)`：两个交易员在同一天推荐同一只票，
是两个要分别打分的判断，不是一个覆盖另一个。

`virtual_portfolio` 的去重同理 —— **两个交易员持有同一只票是比较在生效，
不是重复下单**；只有单个账本不能持有它两次。

净值曲线存在 `daily_snapshots` 里，`data_type` 从 `equity_mark` 变成
`equity_mark:<trader_id>`，默认交易员保留原来的 key，所以历史记录点
不会被重置成零。

## 旧账本怎么办

第一个配置文件出现的那一刻，`default` 交易员就不该再开新仓了 ——
没人配置过的策略不应该继续买入。但它手上还有 7 个持仓和 5 笔挂单，
那些仓位带着真实的止损和活跃论点，**扔下不管等于让它们一直挂到到期**。

所以 `load_traders()` 有两个模式：

- `load_traders()` —— 需要**被管理**的账本，包含还有持仓的 legacy default
- `load_traders(scanning=True)` —— 允许**开新仓**的交易员，不含它

管理一个账本和往里加仓是两种不同的权限，混在一起就会出现「没人配置过的
策略还在买」。

## 现在的状态

```
traders/pullback.yaml    回调派  100万  等回调
traders/breakout.yaml    突破派  100万  追突破
```

两个文件的差异**只有 extra_prompt 那段话**——同一批候选股、同一批工具、
同一个市场。实测同一只票（锡业股份，现价 34.92）：

| | 介入区间 | 宽度 | 止损 |
|---|---|---|---|
| 突破派 | 33.50–35.00 | 4.3% | 33.00 |
| 回调派 | 34.50–35.50 | 2.8% | 33.30 |

哪个假设对，由撤单率和净值曲线回答，不由任何一方的论述回答。

### 顺带修掉的一个 bug

97 笔撤单里约 80 笔是「主线走弱」，而下单时主线**强度只有 0-2**——
系统自己标成 watching/dead 的线，盘中打分函数照下不误，隔一轮再撤掉。

它在创建自己已经决定不会持有的订单，然后把这些撤单算进「介入质量」
统计，当成关于定价的证据。`MIN_THEME_STRENGTH` 现在在建单和查单两处
共用一个常数，不会再错开。

需要多少样本才能分出胜负？如果比的是收益，那是几百笔的事（见
`docs/thesis_design.md` 里那笔算术）。但**撤单率**不一样 —— 它的噪声是
二项式的，不是收益方差，几十笔就能读出来。所以第一个会有答案的问题不是
「谁更赚钱」，而是「谁的订单更容易变成持仓」。
