## 1. 总结论

**“先方向、后个股”的研究组织方式值得保留；但现在的交易逻辑、证据传递、对照实验和绩效计算尚未完全闭合，不能直接进入用于判断策略胜负的正式验证。**

纠正此前“S0–S4 基本完成，只剩资金流数据卡点”的过度概括：代码中还存在模型调用前可触发的预算异常、A/B 决策信息集不一致、初始净值遗漏和报告生成链缺口。拿到资金流数据不会自动解决这些问题。[E1][E2][E3][E4]

批准继续的是：有边界的修复、真实内部链路的工程测试、隔离的前向原始记录。暂不批准的是：宣称 Sector-First 优于 incumbent、放宽数据真实性门槛、切换 active policy 或让 Agent 批准自己的候选。

项目的目标应压成一句话：

> 在可验证的当时信息下，识别有共同驱动的机会，选择有相对优势且可成交的交易载体，并在事先限定的组合风险内行动。

板块强，不等于还有空间；股票好，不等于当前价格值得买；方向判断正确，不等于这笔交易能赚钱。行业动量研究支持分层研究的必要性，但相关经典研究主要讨论 6–12 个月窗口，不能直接证明本项目的短周期题材策略。[R1]

### F01：预算异常在模型调用前触发

`sector_selector.propose()` 仅在 `tools` 非空时导入 `use_research_budget`，但传入预算后无论有没有工具都会使用它。真实调用方传 `tools=[]` 和一个共享 `ResearchBudget`，因此命中未绑定局部变量路径。[E1][E2]

隔离复现：`UnboundLocalError`，失败前模型调用数为 0；无预算控制组通过。`t1_decider` 也需要检验相同结构，不能仅修一个函数就声明全链完成。[E12]

修复要求：预算上下文与工具是否非空解耦；有/无工具 × 有/无预算共四种组合都走真实 proposer。允许替换模型 SDK 的外部执行边界，不得替换 proposer 本身而只检查传参。

### F02：初始净值与收益计算错误

回放只输出交易日结束净值，比较器把第一行当成初始本金。初始 100、首日 95、最后 100，正确总收益 0%、最大回撤 5%；当前抄录逻辑得到收益约 5.263%、回撤 0%。回放文字摘要又使用名义初始本金，与 comparator 分母不一致。[E2][E3]

修复要求：显式保存交易前初始账户状态；首日费用与盈亏进入收益和回撤；全部摘要使用同一净值口径；初始标记行不是额外交易日。验证无外部出入金的恒等式，出入金情形必须拒绝或有另行声明的收益计算方法。

### F03：上游研究没有完整到达下游

方向 selector 输出 thesis、counterevidence、unknowns、invalidations，但调用方主要保留方向 ID。stock selector 研究后，planner 收到的是原 panel 中的股票行，不是完整的研究事实与反证包；planner 本身又无工具。[E1][E2][E13]

风险不是只丢日志，而是上游查过 ATR、价格结构或事件，下游定价格时却没有这些事实。改善是显式传递一份共享的、有版本和引用的研究结果，而不是再加一个“专家评审 Agent”。

### F04：A/B 对照同时改变多个因素

A 的 `_build_panel()` 通过当前概念映射获得标签，Sector-First 使用 PIT membership；风险归因使用同一 archive 并不能修正决策输入不一致。A 的一体化决策与 B 的方向→个股→planner 也并非只改变了候选发现顺序。[E2]

可接受两种实验，但必须分名：原样 incumbent 与新系统比较整体实用性；清洁对照采用共同信息和共同下游，只改变机会发现。不得偷偷改 incumbent 再沿用原基线名称。

### F05：命令存在，但产物链尚未自动闭合

`run-matrix` 编排 A→B→freeze→C→D→compare，comparator 要求 stock report 及相应 direction report，但这条路径没有完整调用 outcome 成熟与分层报告生成。[E4][E3]

修复要求：从空目录开始跑，真实内部编排、Journal、标签、执行账本和报告都参与；只替换外部模型/行情服务。报告必须绑定 run/arm/world/protocol 和标签截止时间。旧目录残留文件不能让新实验“通过”。

### F06：统计问题不是再加一个 bootstrap 就解决

当前主指标可以名为组合净收益，CI 实际计算日收益差均值，却使用同一个最小改善字段。整个窗口提升 0.1 个百分点不等于每天提升 0.1 个百分点。另有 4×30 日的文档设计与逐窗口 minimum_days=50 的实现矛盾。[E3][E4][E5]

隔离日期例子中，60 行相同日期不会被拒绝，最终折叠成 1 个 daily-return 项。样本量必须来自真实、唯一、对齐交易日，不能只信 metadata。风险否决、收益改善、数据不足和统计不确定要分别输出。

### F07：hash 和人工签字不是数据真实性证明

capability gate 检查报告内容、等级和非空核验字段，但底层资金流读取仍按 trade_date。资格检查不能只存在于推荐的高层入口，而低层 replay/compare 接收同名实验却缺少对应消费证据。[E6][E2][E3][E4]

改善：actual read set→data version→available_at→world hash→experiment identity 闭合；缺版本的数据只能降级或排除，不能人工写 A 就变成严格 PIT。证券全集、历史名称/ST/停牌/退市和公司行动同样需要审计，first-bar 日期只是代理，不是完整历史证券主表。

## 4. 逐环节评审

### 4.1 投资任务与市场环境

**保留：**市场状态、研究注意力和硬风险限制分层；不把若干相关观测压成万能总分。[E5]

**问题：**流程偏向“每天发现新股票”，但交易员首先应管理已承担风险。现有持仓、待成交订单、旧论点失效和相关风险额度，应先于新机会。研究周期、下单时点、标签期限和实际持有期也必须一致。

**改善：**先生成账户状态与新增风险预算，再研究方向。第一轮只明确一种现有交易行为；趋势回撤、突破延续等形态须有独立契约与实验，不能一次全部加入。市场状态可影响研究和提案，但不得由模型改写硬风险上限。

### 4.2 数据、事件与预期

**保留：**PIT 成员、不可覆盖快照、缺失与零值区分、未知来源不冒充可用。[E5][E6]

**问题：**“数据表存在”“有 trade_date”“有 hash”“有人填写审核字段”分别只证明有限事实。公告发生、公布、采集和实际可用时间不同；复权、证券状态和后续修订均可能污染历史。工具返回的 as-of 声明也要有真实查询支持。

**改善：**明确每条事实的 source、available_at、vintage 与单位；在数据消费者处按截止时间过滤。资金流是待验证增量，不应阻止其他不依赖资金流的问题。新建全流程无资金流的实验协议，不放松原四臂要求，也不声称已有 D 就等于全链 no-flow。

### 4.3 板块与方向研究

**保留：**相对收益、广度、头部依赖和 leave-one-out 有助于避免一只股票为整个方向制造证据；但都不是独立 alpha 的证明。[E7]

**问题：**近期收益、广度和广度改善高度相关。固定 Top 8→0..3 的硬漏斗可能只解释已经上涨的主题，遗漏早期变化。当前强与未来仍有收益空间是两回事。

**改善：**方向卡同时说明发生了什么、价格如何反应、还有什么未兑现、什么事实会推翻判断；阶段是推断，不冒充原始事实。保留低成本 discovery 观察队列，初期不增加交易名额。板块优先是注意力分配，不是永远不能纠错的准入教条。

### 4.4 板块内交易载体比较

**保留：**板块轮转、去重与重叠主题归因；当前涨幅/换手排序可以保留为透明基线。[E8]

**问题：**“较强板块→较强/高换手股票→模型补解释”可能仍是追涨榜。行情观察对象、可买对象与最优交易载体不应混在一起。主主题目前受哪个方向先提供股票影响，遍历顺序不等于经济论点。[E8]

**改善：**不可买龙头仍可作为行情证据；交易名单受资格和成交条件约束。Agent 必须比较同方向备选的直接关联、位置、失效边界与流动性；不能把“涨得少”当补涨理由。主主题由带证据的交易论点确定，其他主题用于风险暴露；这项行为变化另开版本，不混入修 bug 的 PR。

### 4.5 Agent 分工与证据传递

**保留：**方向、选股、计划的职责分离和边界校验；不强制多 Agent 团队。简单、可组合的 workflow 是合理起点，但增加阶段需要可测收益。[R2]

**问题：**阶段间共享了预算，却没有共享完整研究依据；工具预算也没有覆盖全部模型 token、时延、失败率。无工具 planner 不应被提示去调用工具，未使用的旧 prompt 不应作为运行行为证据。[E1][E2][E13]

**改善：**一个 Trader 对整笔决定负责，可分阶段调用；共享研究对象包含方向论点、股票比较、实际读取事实、反证、未知、失效、期限、cutoff 与引用。planner 使用这个对象提出计划，代码约束数值与权限。未选择不自动等于模型明确拒绝；理由不能事后补写。

### 4.6 交易计划与仓位

**保留：**入场区间、允许不交易、planner 不得换候选。[E13]

**问题：**entry/stop/target/reason 能表示价格方案，但不是完整交易计划；格式合法不代表价格有证据。期限、条件失效、计划风险、没有进展时的退出和后续管理尚需统一。T+1 与涨跌停使计划止损价不等于可保证的最大损失。[E9]

**改善：**模型解释为什么现在、为什么该位置、何时失效；程序计算仓位。数量由计划风险、单票限制、相关主题剩余额度、流动性和可用资金共同约束。具体阈值事前冻结，不在本报告中冒充最优参数。跳空/卖不出压力情景另列，不把账面止损距离当最坏损失上限。

### 4.7 组合风险

**保留：**一笔仓位计入多个关联主题，missing mark 不当成零；已有执行/风险内核继续复用。[E10]

**问题：**新的主题快照主要在收盘输出，不能代替新增订单前的全量重叠风险校验。最大单个主题标签暴露也不等于完整相关风险簇；名称不同的方向可能承担同一风险。此处不是断言旧内核完全没有风控。[E2][E10]

**改善：**研究前分配预算、下单前再次校验并原子占用；一并考虑已有仓位、挂单和本批订单。先把确定的相关主题与并发额度做对，再逐步增加行业、风格和流动性风险。不可用换主标签规避集中度。

### 4.8 执行、退出与交易规则

**保留：**一个 Intent/账本内核、真实拒绝、模型故障不阻止结算；日线无法确认的路径不捏造成成交。[E2][E9]

**问题：**晨扫、盘中、开盘回放和 synthetic-close 并非同一种行为。`agent_exits` 还牵连收盘买入，导致退出能力和买入时点耦合。日线开盘模型不能证明盘中承接或回踩能力。部分流动性限制仍需从“报告”升级为执行约束。[E2][E4]

**改善：**首版冻结一种可复现执行语义；退出与收盘买入分开配置；计划期限和订单寿命一致。费用、规则、公司行动、限制与行情单位按适用日期核验。报告披露未成交、延迟、受限、未平仓头寸与终端估值，不只看成交样本。

**已核实的规则例子：**上交所 2026-04-24 公告明确主板风险警示股票涨跌幅限制由 5% 调为 10%，2026-07-06 生效；基线 `market_rules.py` 仍保留 5% 并称缺一手来源。至少 SSE 分支需要按生效时间处理，不能直接泛化为所有交易所同日同规则。默认不交易 ST 可能使它暂未触发，但不能证明规则服务完整。[E14][R3]

### 4.9 复盘、Dream 与演化

**保留：**预测、真实损益和过程分离；未成交不是零收益；观察机会损失，治理边界独立于模型自评。[E11]

**问题 A：缺失可见不等于偏差已消失。**方向 outcome 保留分母，但收益均值/中位数只来自有结果成员。如果缺失与高风险相关，仍可能偏乐观。缺 bar 的 fixture 不能冒充完整退市处理。[E15]

**问题 B：实验问题会被学习反馈改变。**回放 `_learn()` 与后续知识输入使各臂积累不同经验；这可以是自适应系统研究，却不是纯固定架构比较。第一轮必须冻结哪些经验可影响决策。[E2]

**问题 C：旧 shadow 不可直接复制。**`open_run` 接受过去 opened_on；process 批量写样本后再取前 N 封存，没有在入口约束真实注册时刻或精确写入样本数量。按顺序取前 N 并不证明已经发生择优挑选，但确实没有满足严格样本封存契约。旧 gate 的均值改善判断也不能代替新策略的组合风险与不确定性判断。[E16][E17]

**改善：**先问改动影响了什么行为，再看风险和结果；记录全部候选与失败，禁止反复使用同一验证集挑赢家。[R4] 最小隔离前向记录现在就应建设：历史可以回放，真实前向注册与当时决策不能事后补写。完整 S5/gate 可以后做，采集不必后做；但早期原始记录不自动获得未来新策略的晋升资格。

## 5. 改造实验设计：一次回答一个问题

### 5.1 保留 incumbent，新增可归因对照

原 incumbent 原样留存，用于整体系统实用性比较。另建明确命名的清洁对照，共享 PIT 世界、账户条件、下游 planner、执行与退出，只改变候选发现。两种结果不能混称“板块优先增量”。任何修复导致基线变化，要记录 fixed baseline 与 original baseline 的身份。

### 5.2 第一轮另建全流程无资金流协议

该协议从方向、个股卡、工具、新闻/知识输入的可见面一起处理资金证据；现有 D 主要是方向级消融，不得偷换语义。新协议不回答资金流增量，也不降低原 A/B/C/D capability 要求。事件版本不可验证时同样显式去掉该维度，不能使用后知信息。

先比较共同下游下的双榜发现与透明板块发现；再独立问 LLM 方向解释或 LLM 个股选择是否有增量。不要一次放开全部权重、形态和退出规则。

### 5.3 逐快照比较与完整组合路径比较分开

固定世界/账户的选择比较，用于隔离某一次选择变化；完整路径允许仓位随不同交易自然分化，衡量累积系统结果。C 继承 B 的方向不意味着二者后续持仓也天然相同。模型随机性要预注册重复方案并记录请求；重放同一记录用于检查确定性，不是假装重新采样没有差异。

### 5.4 统计量与风险先声明再计算

主指标、评价单位、最小改善单位、比较方向、块长度、重复数、样本日数来源、缺失规则和停止规则都要可执行，而不是仅有必填字段。日收益均值差与完整窗口净收益不能共用一个模糊阈值。

明确 4×30 日是各自诊断还是总体样本；总体汇总不能跨独立账户窗口制造虚假隔夜收益。初始状态、窗口衔接、purge/embargo、标签截止及未成熟边界事前声明。达到 50 日只满足最低门槛，不自动表示统计充分。

### 5.5 历史模型结果不能替代真正前向

严格 PIT 输入仍不能保证现时模型没有通过训练记住历史公司或事件。匿名化等敏感性测试可辅助诊断，但会改变信息集，也不是完整解决方案。历史实验适合淘汰设计；正式晋升必须有冻结候选之后、面对未知结果的前向证据。

## 6. 批准继续建设的目标流程

```text
账户现状、旧持仓、挂单与风险预算
                  |
统一时点世界：可见事实、来源、数据版本与能力
                  |
方向研究 + 全市场发现观察（不偷加交易名额）
                  |
同方向交易载体比较
                  |
共享研究结果：论点、事实引用、反证、期限、失效条件
                  |
交易计划提案
                  |
确定性组合校验 + 数量计算 + 原子化风险额度占用
                  |
原 Intent / 执行 / 账本 / 结算
                  |
预测、损益、过程、机会损失分别归因
                  |
有限行为改动 -> 隔离验证 -> 真实前向证据 -> 独立人工批准
```

Agent 负责解释、比较和提出行动；程序负责信息边界、数值约束、执行与结果计算。新闻、公告与外部工具文本只能成为证据，不能变成修改风险、实验或权限的系统指令。研究侧默认只读，写入交易和晋升必须经过明确契约；提示注入防护不能只靠提示词。[R5]

## 7. 最小复审门槛与必需测试

| 门槛 | 可检查的结果 |
| --- | --- |
| proposer 预算组合 | 4 种有/无组合全部通过真实函数；共享预算只消耗一次 |
| 初始净值 | 100→95→100 得到 0% 收益、5% 回撤，首日回报保留 |
| 日期与数值 | 重复日期、乱序、缺交易日、NaN/Inf/缺失净值不得静默通过 |
| 共同信息世界 | 在相同 cutoff 下两种发现方式共享 world identity；未来插入不改变过去可见内容 |
| 研究到计划 | 上游取得的关键反证、价格事实和引用在 planner 输入中可验证；缺必需事实可拒绝 |
| 全链产物 | 从干净目录自动完成 replay、标签与所有必需报告；陈旧文件和身份错配被拒 |
| 事前组合风险 | 仓位+挂单+新订单整体超限被拒；并发占用不能透支 |
| 结果缺失 | 未成熟、数据缺口、停牌和已知退市分开；分母和敏感性可追溯 |
| shadow 注册/封存 | 不能倒填前向身份；预注册样本集合和规模精确冻结；批量/重试不换题 |
| 默认与权限 | 不改 active policy；不引入真实券商；外部文本不提升权限 |

最小修复以 [实施计划](../exec-plans/active/2026-09-20-sector-first-review-remediation.md) 的 Gate G1/G2 为准；不得仅根据勾选数或测试数量放行。

## 8. 最终合伙人意见

**项目值得继续，下一阶段应减少扩张，增加闭合。**

最有价值的不是 Agent 数量，而是一笔交易从当时事实、论点、订单、风险到结果与改进候选的可追溯关系。最危险的是研究流程越来越完整，真实证据却在阶段之间丢失；协议越来越严格，测量和对照却没有对齐。

保留板块优先与原执行内核，先修可运行性、测量和证据传递；建设共同信息、风险和执行条件下的最小实验，同时隔离积累前向记录。先可信地回答“为什么选、为什么买、为什么没买、承担什么风险、改善哪一步”，再让系统学习如何变好。
