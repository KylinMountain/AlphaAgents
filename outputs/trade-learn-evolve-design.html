ALPHAAGENTS / ARCHITECTURE PROPOSAL / 2026-09-11

Trade. Learn. Evolve.把“模拟交易员”变成系统的第一性对象

不是让一组 Agent 更频繁地生成市场报告，而是让一个持续存在的交易员，在有限信息与资金约束下行动，承担结果，从证据中学习，再通过受控实验改变自己的行为。

设计提案 · 待确认基于本地源码静态核查未修改交易逻辑不涉及实盘接入

核心裁决：保留现有交易与研究基础，把架构中心从“任务 → 报告”迁移为“交易员 → 决策事件 → 成交与账本 → 经验 → 策略版本”。
实施顺序：可信交易事实 → 可归因学习 → 可验证进化。不能反过来。

审视范围：架构与原则、交易员配置、订单/仓位/净值、学习回流、holdout、入口与前端。未读取业务数据库、未重跑收益研究、未运行项目测试；下文静态发现不等同于对历史实绩的测量。

01 / PRODUCT THESIS

项目应回答的，不是“今天分析了什么”

而是四个连续的问题：我现在相信什么？我因此做了什么？市场与执行结果证明了什么？下一版行为为什么值得改变？

Trade · 行动并承担结果

有预算、有仓位、有约束，能开仓、持有、减仓、退出，也能明确拒绝交易。每次决策有当时信息、理由、失效条件及可核对的后果。

Learn · 从结果提出假设

区分判断错、定价错、规模错、执行受阻与规则违约。产物是带来源、适用范围和反例的经验候选，不是一段自动生效的“心得”。

Evolve · 通过证据换版本

冻结候选策略，在后续未参与开发的数据上与旧版比较。通过才晋升，失败保留原因，证据不足就等待。没有“每天必须进化”。

“模拟”应模拟交易约束，不是模拟确定性赚钱；“交易员”应有持续身份，不是让每个定时任务临时扮演一个人。

  • 报告是交易状态与证据的读模型，报告生成失败不应阻断记账、风控或标签成熟。
  • 不追求交易次数、Agent 数量、记忆条数或版本发布频率。这些是活动量，不是能力。
  • 目标是在预先限定风险与资源预算内，证明策略相对冻结基线有可重复的净表现改善；不能用更大风险买到“进步”。

03 / DOMAIN MODEL

Trader 不是一个 prompt，也不是一个超大类

Trader = Identity + Mandate + ActivePolicy + Book + WorkingState + EvidenceHistory

身份持续存在；策略按版本变化；资金由账本计算；经验有来源与时间边界。
对象职责与关键字段谁可以改变
TraderIdentitytrader_id、名称、父系 lineage、创建时间；不随策略升级换 ID。用户或管理控制面。
Mandate资金授权、允许的市场/工具、风险硬上限、计算预算、策略边界；版本化保存。外部授权。学习系统不能自行放松限制。
PolicyVersionprompt 内容哈希、模型配置/已知版本、工具契约、选股/定价/持仓/退出策略、检索策略、批准知识快照、适用环境。候选可以生成；活动版本只能经晋升服务切换。
TraderRuntime当前工作状态、待处理事件、读到的信息边界、活动仓位及订单引用；调度多个组件，不吞并其实现。合法事件状态转移。
Decision / Thesis决策目标、预测事件、概率、期限、证据、反证、动作、订单约束与失效条件；不记录不可验证的“心理”。追加新修订，不能改写过去版本。
Order / Fill / Ledger订单意图、订单状态、逐笔成交、费用、现金/库存流水、结算批次。执行与记账内核；LLM 无直接写权限。
Episode / Experience从决策到结果的经历及对应经验候选；一次 episode 可含多决策、多订单、多笔成交。确定性归集 + 学习器提出解释；事实不可变。
Experiment / Promotion父子策略版本、冻结时点、数据协议、比较目标、验证结果、晋升/拒绝/回滚记录。独立评估器测量，控制面按契约批准。

跨对象追溯，不靠股票代码猜关系

run_id / mode / trader_id / policy_version_id / snapshot_id / decision_id
    ├─ forecast_id → ForecastOutcome
    ├─ thesis_id → episode_id
    └─ order_id → fill_id → ledger_entry_id → TradeOutcome

Experience → evidence_episode_ids + applicable_context + counterevidence
Experiment → parent_version + candidate_version + evaluation_protocol_hash

各事件只携带适用字段，主外键补全链路；同一股票可以被不同交易员独立持有。mode 明确区分常规模拟、影子实验、历史回放，禁止混入一套业绩。

交易员生命周期，不等于配置文件开关

active → paused / draining → archived。暂停禁止新风险，仍管理存量仓位；清算中持续处理退出；归档前应无未完成订单或未管理仓位。删除 YAML 不能让持仓失去责任人。故障状态进入保护模式，不能静默变成另一位默认交易员。

04 / OPERATING MODEL

一个事件驱动的交易员内核，多种时间与市场适配器

共享世界原始数据、可见时间、行情质量、市场日历
交易员运行时接收事件、读取状态、检索证据、形成结构化决策
执行与账本风控、订单、成交、费用、持仓与对账
证据与版本治理标签成熟、经验候选、影子实验、批准晋升

快循环：保安全，保持事实正确

行情到达、订单状态变化、持仓触发条件、风险越界、交易日切换。确定性检查不等待 LLM，不等待报告，也不等待下一次复盘。

慢循环：做判断，检验新行为

信息变化足够大时调用模型；结果成熟后归集证据；足够的新证据才发起实验。日程只触发事件，不携带策略规则。

优先模块化单体。一个进程内可有按交易员串行的事件队列；市场读取共享只读快照。账户内状态转移串行、不同交易员隔离执行。单写者或数据库事务配合幂等键；不急于引入消息中间件、分布式 Actor 或多个微服务。

三个模式，共用同一交易内核

  • 常规模拟：实时接收市场数据，只通过 PaperBroker 产生模拟成交。
  • 历史回放：换成 ReplayClock 与历史数据适配器，仍走相同决策契约、风控、成交和记账。
  • 影子实验：冻结候选版本，独立账户与记忆命名空间；不能修改主交易员的状态或活动知识。

“重放记录中的模型输出”可以要求确定性一致；“再次调用模型重新决策”是新的实验，不能承诺逐字或逐笔相同。模型名称、温度与 seed 不足以保证跨供应商升级重现，必须保留请求、返回和已知模型标识。

共享事实，隔离判断

新闻、行情可以共享；“这个主线进入衰退”已经是推断，必须带作者、时间、版本和证据。共享推断只能作为可选研究输入，不能冒充无偏事实。实验时共同输入被冻结，避免一个候选反过来改变另一个的世界。

05 / TRADE

先造一个不会自欺的模拟交易员

统一的决策与执行入口

MarketEvent
  → WorldSnapshot(as_of, available_at, quality)
  → DecisionIntent(action, thesis, constraints, provenance)
  → SchemaValidation
  → PreTradeRisk + cash / inventory reservation
  → PaperBroker(order state machine)
  → FillEvent + fees
  → LedgerTransaction + outbox
  → Position / Cash / Equity projections
  → Reconciliation

入场、加仓、减仓、清仓、自动保护退出全部通过这一条链。模型不能直接调用“改仓位”或“写收益”。风险拒绝、缺数据、模型无响应、主动跳过要有不同状态，不能统一当成“没有交易”。

明确订单状态，不把“触价”当“成交”

submitted → accepted → partially_filled → filled，并有 rejected / cancel_pending / cancelled / expired 分支。取消与成交可能交错；取消请求不自动抹去在途成交。停止损失是交易意图，不保证止损价能成交。

仿真契约最低要求
信息时间区分事件发生、发布、系统接收、决策、订单提交、成交时点。用于决策的信息必须满足 available_at ≤ decision_at；盘后完整 K 线不能生成同根 K 线内的理想成交。
市场规则按证券与生效日期加载交易日历、交易时段、结算、手数/零股、价格限制、停牌与费用模型。不能把一套固定常数当成全部 A 股工具的永久规则；实现阶段再核对官方规则。
可成交性校验行情新鲜度、可用成交量、价格范围、订单延迟与参与率。只有日线时，对同根 K 线先后顺序不明的情况采用预声明保守方案，不挑对策略有利的路径。
现金与库存订单批准时冻结足够资金/可卖库存，取消或剩余失效时释放。费用按实际成交与收费契约记账；买入批次保留可卖时点，不仅保存平均价。
风险不可绕过提交前及成交前均验证需要动态检查的约束；全局 kill switch、单交易员暂停、数据失效保护独立于模型。紧急退出仍尊重可成交性，受阻时记录未解除风险。
失败与幂等唯一命令键、事件序号、数据库事务、outbox 以及消费去重。中断重试不重复成交/收费；有多 worker 时增加锁租约或 fencing，内存锁不能代替跨进程约束。

账本是唯一资金事实来源

总现金 = 初始/外部现金流 + 卖出款 - 买入款 - 实际费用 + 已发生现金权益
可用现金 = 总现金 - 冻结现金
账户权益 = 总现金 + 持仓按规定估值的市值 + 应收权益 - 应付款项
净损益 = 账户权益 - 初始权益 - 净外部投入

已实现盈亏是上述流水的派生指标，不能在卖出款之外再加一次。分批卖出的累计结果从 fills/ledger 汇总，最终退出不能覆盖前面的已实现结果。分红、拆并股、退市等事件需纳入规则适用范围；缺失时标记受影响区间不适合能力评价，而不是悄悄跳过。

价格缺失时可以保留“最后可靠估值”供运维观察，但必须标记陈旧与不确定性；不能用成本价填补后把零波动净值当作有效表现。

06 / LEARN

学习单位是一段决策经历，不是一篇复盘报告

DecisionEpisode 将机会识别、决定交易或放弃、订单反馈、持仓调整、退出、标签成熟串起来。一笔持仓可能含多次决策；一个未成交订单也能提供执行证据。不要只收集赚钱交易。

记录“做了什么”，也记录“没做什么”

交易、持有、放弃、风控拒绝、超时缺答、取消、未成交、部分成交、提前退出。明确机会全集与覆盖率，防止通过只记容易的样本制造高胜率。

学习可以持续，策略不必持续变

工作记忆可记住新事件和已作决定；账本可持续更新。可执行经验、检索权重、校准器和 prompt 都属于行为依赖，改动必须进入新版本。

至少拆开三类结果

结果对象测量什么不能混淆什么
ForecastOutcome显式声明的目标事件是否发生，Brier / log score、校准、预测覆盖率。未买入也可验证预测；被迫提前退出不能覆盖原预测的固定期限标签。映射概率与模型显式概率注明来源。
TradeOutcome真实模拟 fills 对应的净损益、费用、持有期、资金占用、MFE/MAE、成交缺口。看对方向但没成交不等于赚到；原预测跑赢但实际交易亏损，两项都应如实保留。
ProcessOutcome是否遵守当时已冻结的决策与风险规则；是否受延迟、缺数据或系统错误阻碍。遵守规则不保证盈利；盈利也不豁免违规。系统故障与策略判断错误分开统计。

标签有 pending / matured / censored / revised 生命周期。持仓尚未退出不能先贴盈利/亏损终局标签；预测期限按固定市场日历对齐，不因股票缺 K 线就延长。保留 label_available_at，后来的修正追加版本，不改写当年可见记录。

经验应该长什么样

ExperienceCandidate
  claim                 : 一个可以被否证的行为改进假设
  applicable_context    : 在什么环境/条件下适用
  proposed_behavior_delta: 相比当前版本具体改哪一处
  evidence_episode_ids  : 正反案例，按ID引用
  alternatives          : 其他可解释结果的因素
  observed_n / window_n : 样本与独立窗口口径
  data_quality          : 已知缺口、代理变量、偏差
  status                : observation / hypothesis / testing / validated / retired

确定性指标先计算，模型再解释与提出假设。模型可以说“可能是进入太迟”，但不能仅凭叙述把它判成原因，更不能写出“有效性评分=高”并自动启用。

反事实用于研究，不能偷渡成历史利润

“不退出会怎样”“采用另一种入场约束会怎样”必须事先定义替代策略，并在相同信息、执行规则与资本限制下重放。结果存独立 CounterfactualOutcome。不能事后寻找最优买卖点，也不能把未成交机会的最高涨幅称为损失。

某条经验被成功交易引用，只能证明共现；要证明它的增量贡献，需比较有/无该经验的冻结版本。最小可理解改动优先，但允许有依赖关系的策略包一起实验，代价是不能把收益精确归给其中某一条。

07 / EVOLVE

进化的产物是策略版本，不是不断增厚的 prompt

observation → hypothesis → draft candidate → frozen
                                    ↓
                    forward shadow evaluation
                                    ↓
              insufficient / rejected / validated
                                           ↓
                            approved → promoted
                                           ↓
                              monitored → rollback / retire

一份冻结版本要冻结所有行为依赖

包括 prompt 实际内容、模型配置、工具接口、选股与排序、入退出和规模策略、知识条目快照、检索排序与过滤、校准器，以及评估所依赖的仿真/数据版本。只有一个文件名或模型别名不够；冻结后文件变化不能悄悄改变实验。

  • 学习器的权限：提出候选、追加证据、申请实验；不能改活动策略、风险硬上限、历史结果或评价标准。
  • 评估器的权限：基于独立结果计算指标与证据等级，不读取模型的“自我评分”作为真值。
  • 晋升器的权限：检查被冻结的协议与审批条件，原子切换一个活动版本指针，留下批准者与理由。
  • 首版建议：即使自动评估通过，也经人工批准晋升；验证流程成熟后才考虑按窄范围授权自动化。

主版本、候选版本与非 LLM 基线

先保留一个主版本（champion）、一个候选（challenger）和一个冻结的简单基线。两套账户从同一账本快照分叉，此后独立持仓、独立占用资金，接受同样的原始市场流、成本模型与风险授权。不把候选强行成交到主版本账上。

比较“整个交易员”时允许其选择不同机会；比较“某个定价/退出模块”时应固定其他上游依赖。简单基线、无记忆版与冻结旧版回答不同问题，按实验目的选择，不一次堆出大量组合。

拒绝必须真的阻止生效

新原则不能直接 active；学习后更新现有 playbook 权重、退休条目、改变检索顺序同样可能改变行为，也要生成候选版本。因污染数据或系统故障触发的安全禁用走独立应急流程，标记原因，不能包装成已验证策略改善。

切版本只改变未来，不修改已经发生的交易

默认让存量仓位继续由建仓时的策略版本管理；如需新版本接管，产生显式 handover 事件。切换时同样处理未成交订单、在途决策与过期快照，不能用旧版报价偷偷在新版账户开仓。回滚恢复行为版本，不“撤销”真实记录的模拟成交或亏损。

08 / PROVING IMPROVEMENT

“学到更多”与“变得更好”必须是两件事

评价层关注指标门槛原则
完整性：能否相信结果账本对平、数据质量、来源链完整、规则违约、影子隔离、事件重放一致性。硬门槛。此层失败，收益和学习结论不进入晋升评价。
交易：是否更有效扣费净值、与可实施冻结基线的差异、回撤/尾部风险、敞口、换手、容量、成交率与资源成本。同资金/风险/成本协议比较；事先声明主指标与不能退化的约束。
判断：是否更准确匹配目标事件的 Brier / log score、校准、覆盖率；风格残差作为诊断。不允许换预测事件、挑交集或放弃难题后仍用相同分母。不同目标不能混池。
进化：是否有增量冻结候选相对父版本的前向配对差异、置信区间、独立窗口数、不同环境稳定性。不能因“未发现显著变差”就声称“证明不退化”或“证明改善”。

两种对照不可混为一谈

  • 预测对照：冻结共同机会面板、目标、时间戳与期限；记录全部输出和缺答。缺答的覆盖率/处理规则预先定义，不能只比较双方恰好都看好的股票。
  • 整本交易对照：从相同初始状态分叉后各自行动；按对齐的时间区间比较账户表现。候选选股不同不应被交集筛掉。
  • 不同交易员横向排名：风险授权或资金规模不同，不能直接以金额排名。先统一评价协议或分组展示，提示非可比性。

前向、隔离、预注册

  1. 候选冻结时登记训练数据可见截止、评价区间、主指标、最小效应、容忍边界、风险约束与检查时点。
  2. 评价记录不得流入候选构造、反思或知识检索。未来重新开放给研究的数据，不能继续充当未污染 holdout；新候选等待新的前向区间。
  3. 重叠持有期和同日股票结果相关，不能把它们当独立观测做简单 t 检验。按时间块/市场簇测不确定性，并清除训练与验证标签区间的重叠泄漏。
  4. 遵守项目 n≥50 的最低治理要求，同时报告样本单位、独立窗口数、环境覆盖和置信区间。50 笔不是充分证据，更不是50笔高度相关交易即代表50次独立试验。
  5. 控制候选数量、重复查看和多重比较；不让“每天试一次直到偶然过关”变成进化机制。预算、停止规则及统计处理在实验前约定。
  6. 若主张收益改善，应给改善区间与风险约束；若主张低成本下不劣，应检验事先定义的不劣边界，并给成本收益。证据不足保留旧版。
两个无法靠漂亮回测消除的限制：历史回放无法完全排除模型预训练中已知未来的信息；PaperBroker 也不等于真实成交。因此历史实验用于筛错与开发，前向模拟是必要证据，但仍不能直接证明实盘可实现收益。

这里的门槛是评价设计，不是已测出的表现。本轮不引用未经复核的外部研究收益，也不为项目虚构胜率或年化指标。

09 / PRODUCT EXPERIENCE

首页应是一张“交易员工作台”，不是资讯门户

当前导航仍以资讯、异动、主线、报告与虚拟持仓为主（web/src/App.jsx:17–31）。不是删除这些能力，而是将其组织到“服务谁、导致了什么决策”的上下文中。

Trade 工作台

当前交易员/活动版本、净值与数据质量、可用/冻结资金、持仓与未成交订单、当前 thesis、下一触发条件、最近决策与拒绝原因。

Learn 经历簿

按 episode 展示信息 → 判断 → 订单 → 成交 → 结果。可以查看看对未赚、看错但守纪、系统受阻、经验候选与反例。

Evolve 实验室

版本差异、冻结时间、假设与协议、样本进度、主/候选对照、晋升原因、拒绝原因及回滚历史。

资讯、主线和研究报告变成辅助视图；用户从每个数字能追到事实。首页必须直说“证据不足”“行情陈旧”“账户不可比”，而不是所有空值显示为零。

检验产品是否真正转向交易员：关掉报告生成，订单管理、风控、记账、结果核验和实验仍应运行；关掉交易员运行时，则产品不应还能假装自己完成了核心任务。
10 / INCREMENTAL MIGRATION

围绕已有工程收拢责任，而非重新造一套系统

阶段具体边界完成后的能力
P0a · 契约与证据先统一架构/依赖规则、ID、模式、时钟、数据可见性与账本 schema。审视旧数据可恢复程度；明确未验证规则不再直接改变行为的方案。能定义“谁、哪个版本、何时、据什么做了什么”，并区分旧记录证据等级。
P0b · 可信账本从 data/portfolio.py 拆出成交/现金流水、结算批次、订单状态和投影；改造 portfolio_risk.py 的净值来源；显式绑定 thesis/prediction。一次买入—加仓—部分退出—平仓能对账；所有盈亏与费用可追踪。
P1 · 统一交易内核morning_scan / intraday_monitor / book_manager / exit_decision / thesis_monitor 只提交统一意图；调度转事件，旧调用变薄适配器，全部风险走同一入口。同一交易员逻辑能常规模拟与历史回放；报告故障不影响保护与交易事实。
P2 · Episode 学习替换 _feed_close_to_learning 的启发式关联；scoring / lessons / principle_scoring / context_builder 消费明确结果对象和批准知识。三类结果不互相覆盖；经验可追溯、有反例，未成熟标签不提前学习。
P3 · 受控进化将 holdout_gate 升级为版本级实验评估；新增版本注册/影子账户/单一晋升操作；阻止 create_playbook / reinforce 等直接改变当前行为。拒绝真正阻断，候选可积累前向证据，批准切换与回滚有审计。
P4 · 产品收口server/API 与前端围绕 trader/episode/experiment 构造投影；合并触发同一业务的旧入口，减少平行报告链。用户看到一个持续交易与成长的主体，而不是几组互相不完全相认的页面。

建议的职责落点，不是本轮已创建的目录

data/          记录模型、repository、事件/账本持久化、确定性基础状态转移
sources/       外部数据边界、标准化与接收时间
 tools/        市场查询/计算能力（沿用，不存交易员业务状态）
evolution/     episode 评价、经验候选、实验测量、版本治理规则
pipeline/      TraderRuntime 编排、事件调度、执行流程服务
agents/        DecisionPolicy / Learner 的模型实现与调用适配
server/        API、读模型与管理控制面

上述落点沿用当前 lint 层序。低层编排依赖结构化策略接口，由更高层组装并注入模型实现；不能让 evolution 反向 import pipeline，也不能让存储模块调用 Agent。若需新增最底层 domain/contracts 包，应先通过依赖规则与结构测试确认，再迁移；不先大规模搬文件。

存量数据迁移的底线

  • 有充分旧明细时才重建账本，并逐账户核对；缺少成交/费用记录时不能补造历史 fills。
  • 无法可靠还原的旧历史保留为 legacy 证据，以明确来源和不确定性的期初余额/库存快照开始新核算期；不能把新净值拼接成已验证的旧业绩。
  • 建立新投影并对账后再切读路径；避免长期双写两个事实源。迁移中保留恢复路径与数据备份，具体操作另行确认。
  • 这一轮只交设计；后续实施再按项目要求建立执行计划、补失败测试、运行完整测试和架构检查。
11 / EXECUTABLE ACCEPTANCE

不用“更加智能”验收，用能失败的测试验收

以下数量为建议的工程验收目标，不是已完成测试结果；统计门槛还需按策略频率与数据功效预注册。当前未运行项目测试。

契约建议的机器可检查标准
会计正确整数最小货币单位或固定精度核算；在显式舍入策略下，对账差额为 0。覆盖买入/加仓/多次减仓/最终平仓/费用/公司行动，空仓权益等于期初权益加净外部现金流与累计净损益。
身份完整100% 成交、账本、结果记录可追到 trader/run/version/decision；必需外键缺失 0 条；同股同日两位交易员及多个版本的归属串线 0 次。
幂等与恢复生成至少 10,000 条合成事件并注入重复、乱序、重启；每个 fill 仅一次经济影响，最终投影一致，无负库存/非法状态。通知可重试，但不可重复记账。
交易约束测试覆盖可卖批次、冻结现金/库存、停牌、价格限制、缺量、陈旧行情、取消/成交竞态、同根 K 线歧义；所有路径经过统一风控与执行器，直接改仓位的业务旁路为 0。
时间与重放任一决策输入均满足可见时间约束；固定输入/模型返回/仿真版本重放两次得到相同规范化事件与账本。重放 hash 排除墙钟审计时间或使用稳定逻辑 ID；后来修订不改变过去输入。
结果互不覆盖同一案例可同时出现预测命中、实际净亏、流程合规三种结果；任何重新评分不覆盖其他结果类型。未成熟、删失与修订标签有明确状态。
闸门有效验证拒绝、数据不足、评估异常时，活动策略及行为依赖 hash 不变；每位交易员同时仅 1 个活动策略指针；禁止未经授权激活知识/权重/prompt。
前向实验隔离candidate 固定 created/frozen_at；shadow 的订单/资金/知识不得写主账户；验证标签与派生记忆不能进入开发上下文；不足 n≥50 时不得晋升，达到后仍执行独立窗口与不确定性要求。
版本切换晋升/回滚具有完整审计；存量仓位与挂单的版本归属清楚；旧决策不会在新版本下无痕执行；回滚前后既有成交与账本记录不变。
去报告依赖注入报告生成超时/异常，订单状态、风控、对账与标签成熟照常完成；禁用某交易员新开仓后，其存量仓位仍持续管理。

最小复审通过条件

先完成 可信资金账本 + 显式来源绑定 + 拒绝能阻止行为变更 的集成测试，再讨论更复杂的学习算法。后续每一阶段都遵循项目既有测试、lint_harness 与 lint_docs 检查；本次没有把静态检查包装成测试通过。

12 / RECOMMENDED DECISIONS

建议现在确认的五个方向

  1. 产品身份：AlphaAgents 是模拟交易员的持续运行与受控成长系统；研究工具与报告围绕它服务。
  2. 首版边界：专注现有 A 股模拟，不接实盘；先一个完整主交易员、一个候选版本与冻结基线，证明纵向闭环。
  3. 自治边界：模型负责判断与提出改进；确定性内核负责约束、执行、记账；独立证据与审批负责晋升。
  4. 技术形态：模块化单体、按交易员隔离状态、轻量事件与不可改写账本；先收拢事实源，不做大规模基础设施扩张。
  5. 实施优先级：先修复会计和来源，再统一执行与学习对象，最后接通版本实验和交易员工作台。

明确暂缓

在线 RL/模型权重自更新、交易员自动改生产代码、无上限记忆积累、每天自动放大资本、多个角色辩论投票、复杂“性格/情绪”数值以及仅凭短期排名淘汰交易员。它们都不能替代可信结果与前向验证。

下一步最有价值的工作：以“一个交易员的一次完整交易经历”为纵向切片，先让信息、决策、订单、成交、资金、退出、评价全部可追溯，再用同一条事实链驱动经验候选和版本实验。

一句话：让交易员承担结果，让学习提出假设，让进化服从证据。
