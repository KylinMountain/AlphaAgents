# traders/

一个交易员就是这个目录下的一个 YAML 文件。加一个策略 = 写一个文件，
不需要改代码。

目录为空时，系统按内置的 `default` 交易员运行，行为与引入多交易员之前
完全一致 —— 这个特性在被用到之前不产生任何成本。

## 为什么是文件

进化需要变异和选择。选择那一半**还没有接线**（`holdout_gate` 会在冠军和挑战者
之间跑配对检验，但见下方更正），而挑战者是从**已经成功的交易里**挖出来的，
也就是说它们是过去分布的产物。只从自己的成功里学习的系统，最后会收敛到自己身上。

> **2026-09-12 更正：** `holdout_gate` 曾被 `lessons.post_review` 每天调用，
> 但拿到的是 `run_gate("daily_playbook", today, today)` —— 留出窗口长度为 0，
> 三次运行（`gate_decisions` 表 09-08 / 09-09 / 09-11）全部以
> `validation_days: 0` 弃权，一次都不可能晋升。Phase 1 因此**主动断开了这个调用**
> （理由见 `lessons.post_review` 的 docstring）。所以下面那条链里的
> `→ holdout_gate → 保留或归档` 目前**没有实现**；把它接回来需要**候选绑定**的
> 前向协议，属于 Phase 4（`docs/TRADER_CORE_DESIGN.md` §14）。

把交易员做成文件，改变的是一次变异的成本。而且因为变异**就是一个有固定
schema 的文件**，复盘 agent 最终可以自己写一个出来：

> "25 笔挂单撤了 22 笔，其中 13 笔是等回调的时候主线先死了。
> 我想试试追突破，30 万，跑两周。"
> → `traders/breakout_v2.yaml` → holdout_gate → 保留或归档

和失效条件词表是同一个设计：给 agent 一套受限但够用的语法，而不是任意权力。

## 字段

| 字段 | 默认 | 说明 |
|---|---|---|
| `id` | 文件名 | 唯一标识，写进每一笔持仓/论点/预测。不能是 `default` |
| `name` | = id | 报告和通知里显示的名字 |
| `capital` | 1000000 | 自己的本金，独立于其他交易员 |
| `prompt_file` | `morning_scan.md` | `alpha_agents/prompts/` 下的提示词文件 |
| `default_size_pct` | 0.03 | agent 没说仓位时的默认值 |
| `max_position_pct` | 0.10 | 单票上限（兜底，不是目标） |
| `default_horizon_days` | 5 | 论点没写期限时的默认持有期 |
| `enabled` | true | 设 false 暂停，历史数据保留 |
| `extra_prompt` | 空 | 追加在提示词末尾的「你是谁」，晨扫和卖出决策都会看到 |
| `note` / `tags` | 空 | 给人看的备注 |

## extra_prompt 决定一切策略差异

看什么、偏好什么、买在支撑上方还是阻力上方、什么时候不出手 ——
全在这段话里。回调派和突破派拿到的是同一批候选股、同一批工具、
同一个市场，**区别只有这段话**。

## 介入价不在这个文件里

这里**没有** entry_style 之类的字段。介入价、止损、仓位全部由 agent 自己
调 `get_price_levels` 算 —— 那个工具返回均线、20/60 日区间、支撑阻力、
日均波幅（atr_pct），**不返回任何建议**，买在哪里是判断。

这一点曾经不是这样：盘中任务里写死 `entry_low = price * 0.97`，
113 笔订单里 109 笔是这么来的。给这个常数起名叫「风格」放进配置，
只是把「那条路径上压根没有 agent」这件事包装成了一个决策，
而且把一个交易员能变成什么样，卡死在 Python 字典里的三个值上。

判断标准很简单：**如果 agent 有工具能算出来，就不该写进配置。**
配置里剩下的是它算不出来的东西 —— 给了它多少钱、读哪个提示词、
不能突破的兜底上限。

## 各自独立的东西

资金、持仓、挂单、论点、预测、校准曲线、盲点率、一致性、决策质量、
净值曲线、回撤、板块集中度 —— 全部按交易员分账。

**共享的是世界**：行情、主线状态、快讯、工具。那些是事实不是策略，
复制一遍只会让成本翻倍。
